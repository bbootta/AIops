번역 에이전트팀의 오케스트레이터로서 다음 파이프라인을 실행하라. 인자: $ARGUMENTS

## 준비

1. 인자를 해석한다: 원문 파일(들), 도착어(로캘), 추가 지시(독자·어체·마감 형식 등).
2. 도착어가 없으면 원문 언어를 보고 기본값을 정한다(한국어 원문 → en, 그 외 → ko). 원문 파일이 없거나 읽을 수 없으면 중단하고 사용자에게 알린다.
3. 작업 디렉터리를 만든다: `translation/jobs/<YYYYMMDD>-<문서명-슬러그>/`
   - 산출물 경로: `brief.md`, `termbase.md`, `draft-<lang>.md`(→ 최종본), `review-accuracy.md`, `review-fluency.md`, `delivery-report.md`
   - 번역 최종본 파일명: 원문 파일명에 `.<lang>` 삽입 (예: `plan.md` → `plan.en.md`)

## 파이프라인 (각 단계는 이전 단계 산출물에 의존한다 — 순차 실행)

**1단계 — 분석**: `doc-analyst` 서브에이전트에게 원문 경로·추가 지시·브리프 저장 경로를 주고 번역 브리프를 받는다.
- 브리프의 "미결 질문"에 번역 방향을 좌우하는 항목(독자, 어체, 로캘)이 있으면 AskUserQuestion으로 사용자에게 확인한 뒤 브리프에 반영한다. 사소한 항목은 기본값으로 진행하고 최종 보고서에 남긴다.

**2단계 — 용어**: `terminology-curator`에게 원문·브리프 경로를 주고 확정 용어표를 받는다.

**3단계 — 번역**: `translator`에게 원문(또는 청크)·브리프·용어표 경로와 산출물 경로를 주고 초안을 받는다.
- 브리프에 분할 계획이 있으면 청크별 `translator`를 **하나의 메시지에서 병렬로** 실행한다. 각 청크 지시에 직전 청크의 마지막 단락(문체 맥락)을 포함하고, 완료 후 순서대로 병합한다.

**4단계 — 정확성 검수**: `accuracy-reviewer`에게 원문·초안·용어표·브리프 경로를 준다. 초안을 직접 수정하고 보고서를 남긴다.

**5단계 — 윤문**: `fluency-editor`에게 초안(수정본)·브리프·용어표 경로를 준다. 원문 없이 읽으며 직접 수정하고 보고서를 남긴다.

**6단계 — 최종 QA**: `translation-qa`에게 전체 산출물 경로를 준다.
- 판정이 FAIL이면 지목된 단계를 다시 실행하고 6단계를 재실행한다 (최대 2회 반복, 그래도 FAIL이면 사유와 함께 사용자에게 보고).

## 인도

최종 사용자 보고는 다음만 간결히 전달한다:
- 번역 최종본 경로
- delivery-report의 "사용자 확인 필요" 항목 (있으면 AskUserQuestion 또는 목록 제시)
- 용어집 추가 후보 — 승인 시 `/glossary-add`로 반영 가능함을 안내
- 파이프라인 요약 1~2줄 (수정 건수 등)

중간 산출물 경로 나열이나 단계별 상세 서술은 하지 않는다.
