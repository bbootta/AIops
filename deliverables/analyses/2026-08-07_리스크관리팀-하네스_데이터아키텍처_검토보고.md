## 1. 총평

설계 사상은 은행 실무 기준으로도 잘 잡혀 있다. 그레인·PK를 스펙 수준에서 강제하는
정규 카탈로그, seed+asof 재현성, 수치별 감사 원장(BCBS 239), fail-closed 독립검증
게이트, 2선/3선 검증 분리는 데이터 거버넌스의 뼈대로 손색이 없다.

다만 실행 계층에서 다음 네 가지가 구조적 약점이다:

1. 재현성 규칙이 정작 **진입점에서 샌다** (`asof` 기본값 = 벽시계).
2. 실데이터 인제스트에 **계약(contract)이 없고**, 예상 밖 값은 조용히 유실된다.
3. 독립검증 교환 디렉터리가 **단일 슬롯**이라 버전 간 덮어쓰기 경합이 스킴 자체에
   내재한다 — 현재 걸려 있는 `부적합` 게이트 교착은 우연이 아니라 구조의 산물이다.
4. 핵심 차원 테이블에 **이력(SCD)이 없다** — 팩트는 asof로 축적되는데 차원은
   최신본만 남는다.

## 2. 잘된 점

- **그레인이 1급 개념.** 모든 `TableSpec`은 그레인 선언이 없으면 `SchemaError`
  (`spec.py:98-99`), PK 컬럼 존재·non-null 강제(`spec.py:100-111`), PK 유일성은
  데이터 검증 시 실제 확인(`spec.py:198-202`). 107개 테이블 중 106개 PK 선언.
- **도메인 값을 추정하지 않는 원칙.** 등급은 `models.rating.DEFAULT_MASTER_SCALE`,
  리프라이싱 버킷은 실제 엔진 산출에서 파생(`catalog.py:235, 1142`). 코드마스터는
  카탈로그에서 생성되어(`code_master.py:19-41`) 드리프트를 구조로 차단.
- **세분화 테이블은 복제가 아닌 재유도+대사.** IRB 풀 합계=공표 RWA, 평균 RW
  재계산 일치, 운영손실 회수액=손실등록부 일치를 테스트가 고정
  (`tests/test_datamodel_detail.py:150-161, 247-256`).
- **재현성 설계가 장식이 아님.** 도메인별 전용 RNG 스트림
  (`np.random.default_rng(seed+offset)`, 전역 `np.random` 호출 없음 확인),
  포트폴리오 정규화 후 SHA-256 지문, `RunManifest` + `diff_manifests`
  (`repro.py:46, 214`).
- **fail-closed 게이트가 실제로 막음.** 응답 없음=`응답대기`, run_id/재계산 불일치
  =`부적합`(`validation/independent.py:533-569`), CLI 종료코드 1. 조건부 승인은
  사람이 잔여위험·후속조건을 기입해야 통과(`independent.py:168`).
- **산출물 팩 버전 체계.** `asof/{수행일}_vNN` append-only(`archive.py:97-114`),
  버전 포함 ZIP명으로 클로버 방지, `이력.csv`는 수기가 아닌 `버전정보.json` 스캔
  생성(`archive.py:163-227`). 원장(분기 replace)과 팩(버전 append)의 동기 분리도
  올바르다.
- **수치별 리니지 의도.** `audit_trail.py`가 수치→모듈·함수·규정 조항을,
  `regulatory/provenance.py`가 서식 라인별 실측/파생/혼합/대용 분류를 남긴다.
  동어반복 체크를 스스로 공시하는 `check_strength`도 정직한 설계다.

## 3. 발견 사항 (심각도 순)

### F-1. 재현성 규칙이 진입점에서 깨짐 — HIGH

- `asof` 기본값이 `date.today()`(`pipeline.py:791`)이고 CLI `run`/`report-set`은
  `asof`를 전달하지 않는다(`cli.py:40-47, 78`). 같은 seed·데이터라도 실행 날짜가
  다르면 headline digest가 달라진다 — ARCHITECTURE.md의 "seed+asof 동일하면 산출
  동일" 규칙이 진입점에서 위반된다.
- `case_studies/__init__.py:278`은 `seed + hash(profile.short) % 1000`으로 seed를
  유도하는데, 파이썬 문자열 `hash()`는 프로세스별 salt가 걸려 실행마다 다르다
  (PYTHONHASHSEED 미고정). `forms_fss_asset_data.py:65`처럼 `hashlib.sha256`으로
  바꿔야 한다.

**권고**: `--asof` 필수화(또는 미지정 시 명시 기록+경고), salted hash 제거.

### F-2. 인제스트 계약 부재 + 조용한 데이터 유실 — HIGH

- `--data book.csv`는 스키마·타입·필수컬럼·허용값 검증이 전무한 bare
  `pd.read_csv`(`cli.py:32`). 실데이터가 맞춰야 할 스키마는 `data_gen.py`
  docstring에만 존재한다.
- `_stage_split_books`(`pipeline.py:317`)는 하드코딩된 5개 asset_class로
  필터링한다 — 예상 밖 값의 익스포저는 **SA/IRB 양쪽 북에서 소리 없이 탈락**하고,
  파이프라인 내 완전성 대사가 없다 ("총 EAD = SA+IRB" 체크는 advisory인
  `data_quality.reconcile`에만 존재).
- `run_consistency_checks`에 exposure_id **유일성 검사가 없다**
  (`consistency.py:151`은 SA/IRB 중복만 봄). 실데이터에 중복 행이 있으면 RWA가
  경보 없이 이중계상된다.
- `dq_report`(중복·범위·null률)는 `run_pipeline`이 아니라 거버넌스 ops 페이지에서만
  호출된다(`ops_pages/governance.py:470`) — 전 항목 advisory. 신선도(데이터 기준일
  vs asof) 체크는 아예 없다.

**권고**: 인제스트 시점에 스키마 계약 + accepted-value + 유일성 + 총 EAD 완전성
대사를 **blocking**(FAIL)으로 수행. 실데이터 전환의 전제조건.

### F-3. 독립검증 교환: 단일 슬롯 + 무결성 보호 없음 — HIGH

- `run_id = f"RUN-{asof}-{seed}"`(`independent.py:392`)에 판(vNN)이 없고 교환
  파일명이 run_id 기반이라(`independent.py:100-105`) v01/v02/v03이 같은
  `RUN-20260630-42.request.json`을 덮어쓴다. 현재 디스크 상태가 그 증거다:
  request는 v03의 IVR-3973…, response는 **세 판 어디와도 일치하지 않는**
  IVR-345F…. 검증팀이 작업하는 동안 재실행하면 응답이 구조적으로 무효화된다 —
  현재의 `부적합` 교착은 스킴이 만든 것이다.
- 응답/승인 JSON에 해시·서명이 없다. `request_id`는 request 파일에서 재계산되므로
  쓰기 권한만 있으면 일치하는 응답을 위조해 게이트를 `적합`으로 뒤집을 수 있다.
- request_id가 팩 아티팩트를 커버하지 않는 갭은 코드에 자체 공시되어 있으나
  (`independent.py:492-500`) 미해결.
- 게이트 상태가 GATE.txt·버전정보.json(빌드 시점 동결)·교환 디렉터리(계속 변동)
  세 곳에 기록되어 서로 발산한다 — "현재 게이트"의 단일 소스가 없다.

**권고**: 교환 파일 키를 request_id(또는 asof+판) 기반으로 변경, 응답에 요청
해시를 포함하는 해시 체인 추가, 게이트 현재 상태의 단일 소스 지정.

### F-4. 차원 이력(SCD) 부재 — MEDIUM-HIGH

- `rdm_obligor`·`rdm_exposure`·`rdm_collateral`·코드마스터가 natural key 단독
  PK로 `asof`가 없다(`catalog.py:34-104`). 분기 적재 시 PK 위반 아니면 Type 1
  덮어쓰기 — 두 분기가 공존할 수 없다.
- 팩트 테이블(`crm_rating`, `rwa_result`, `agg_*`)은 PK에 asof를 포함해 축적되는
  비대칭 구조라, 과거 asof 팩트에 **오늘의 업종·그룹·차주 속성이 소급 적용**된다.
- 유일한 버전 흔적은 `rdm_snapshot` 지문뿐이며 start/end/is_current 형태의 이력은
  전무. ARCHITECTURE.md도 이 설계 결정을 언급하지 않는다.

**권고**: 차원 asof 정책 결정 — SCD Type 2 도입 또는 "차원은 최신본만 유지"의
명문화(그 경우 과거 재현은 `rdm_snapshot`으로 한다는 절차 포함).

### F-5. 보관·축적 계층 실질 미작동 — MEDIUM-HIGH

- **보관 팩이 자기 MANIFEST와 불일치.** v03 MANIFEST는 206파일을 선언하나
  디렉터리에는 7파일만 남아 있다(프루닝 흔적). README의 `sha256sum -c` 증빙
  절차가 보관본에서 실패한다. 보존·프루닝 정책은 어디에도 문서화되어 있지 않다.
- **`TimeSeriesLedger`(분기 축적 원장)가 배선되어 있지 않다.** 영속화는 opt-in
  (`html_report.py:96-103`)이고 리포 어디에도 원장 데이터가 0건. 게다가
  `add_from_manifest`는 `asof` 자리에 실행 종료 시각을 기록한다
  (`timeseries_ledger.py:72`). load-modify-save에 잠금도 없다.
- 이력 스캐너가 손상된 `버전정보.json`을 조용히 건너뛰어(`archive.py:172-173`)
  손상 팩이 `이력.csv`에서 사라진다. `next_version`도 스캔 기반·무잠금이라 동시
  실행 시 같은 vNN 충돌 가능.

**권고**: 프루닝 정책 문서화 + 보관 시 MANIFEST를 잔존 파일 기준으로 재생성(원본
MANIFEST는 별도 보존), 시계열 원장을 `archive()` 경로에 정식 배선하고 asof 오기록
수정.
