# ISO/IEC 42001 에이전트 필수 요건 (Agent Compliance Requirements)

이 저장소에서 만드는 **모든 에이전트는 아래 요건을 반드시 충족**해야 한다.
요건은 ISO/IEC 42001:2023 본문(4~10절) 및 Annex A 통제항목에서 에이전트(AI 시스템)
단위로 적용 가능한 항목을 도출한 것이다.

> 참고: ISO/IEC 42001 인증 대상은 조직의 AI 경영시스템(AIMS)이다. 개별 에이전트는
> "인증"되는 것이 아니라, AIMS가 요구하는 통제를 구현·문서화하여 **심사 가능
> (audit-ready)** 상태를 유지해야 한다.

## 적용 규칙

- 신규 에이전트는 아래 체크리스트를 **모두 충족하기 전에는 배포(merge)하지 않는다.**
- 에이전트마다 `templates/AGENT-COMPLIANCE-RECORD.md`를 복사해 적합성 기록을 작성하고,
  에이전트 코드와 같은 디렉터리에 `COMPLIANCE.md`로 둔다.
- 에이전트의 목적·데이터·도구가 변경되면 적합성 기록을 재검토·갱신한다(변경 관리).

## 필수 요건 체크리스트

### 1. 목적 및 책임 (Annex A.2, A.3)

- [ ] **의도된 목적(intended purpose)** 과 사용 범위를 문서화한다. 범위 밖 사용
      (out-of-scope use)을 명시한다.
- [ ] 에이전트의 **책임자(owner)** 를 지정한다. 운영·사고 대응·폐기 결정의 책임 주체를
      명확히 한다.

### 2. 위험 평가 및 영향 평가 (6.1.2, 6.1.4, Annex A.5)

- [ ] 배포 전 **AI 위험 평가**를 수행한다: 오작동·오용·유해 출력 시나리오, 발생 가능성,
      영향도, 완화책을 기록한다.
- [ ] **AI 시스템 영향 평가(AI system impact assessment)** 를 수행한다: 개인·집단·사회에
      미칠 수 있는 영향(공정성, 안전, 프라이버시 포함)을 기록한다.
- [ ] 위험 평가는 에이전트의 목적·도구·데이터가 바뀔 때마다 갱신한다.

### 3. 수명주기 관리 (Annex A.6)

- [ ] **요구사항 명세**: 에이전트가 달성해야 할 기능·품질 기준을 배포 전에 정의한다.
- [ ] **검증 및 확인(V&V)**: 배포 전 요구사항 충족 여부를 테스트로 검증하고 결과를
      기록한다. 실패 시 배포하지 않는다.
- [ ] **이벤트 로깅**: 에이전트의 주요 행위(입력, 도구 호출, 출력, 오류)를 추적 가능한
      로그로 남긴다.
- [ ] **변경 관리**: 프롬프트·모델·도구 변경은 버전 관리(git)하고, 변경 사유를 커밋
      메시지에 남긴다.
- [ ] **폐기 절차**: 에이전트 폐기 시 데이터·자격증명 처리 방법을 정의한다.

### 4. 데이터 거버넌스 (Annex A.7)

- [ ] 에이전트가 접근·처리하는 **데이터의 출처, 종류, 민감도**를 문서화한다.
- [ ] 개인정보·민감정보를 다루는 경우 최소 수집 원칙을 적용하고, 로그·출력에 불필요한
      민감정보가 남지 않도록 한다.

### 5. 투명성 및 이해관계자 정보 제공 (Annex A.8)

- [ ] 사용자에게 **AI 에이전트와 상호작용 중임을 인지**할 수 있도록 한다.
- [ ] 에이전트의 능력과 **한계(limitations)** 를 문서화하고 사용자에게 제공 가능한
      형태로 유지한다.
- [ ] **사고 보고 경로**: 오작동·유해 출력 발견 시 보고·대응 절차를 정의한다.

### 6. 인간 감독 (Annex A.9)

- [ ] **인간 개입 지점(human oversight)** 을 정의한다: 되돌리기 어렵거나 외부에 영향을
      주는 행위(삭제, 발송, 배포, 결제 등)는 인간 승인을 거치도록 설계한다.
- [ ] 에이전트를 의도된 목적 외로 사용하지 않도록 사용 지침을 문서화한다.

### 7. 서드파티 구성요소 (Annex A.10)

- [ ] 사용하는 **외부 모델·API·MCP 서버·라이브러리**를 목록화하고, 각각의 공급자와
      역할을 기록한다.

### 8. 모니터링 및 개선 (9절, 10절)

- [ ] 배포 후 **성능·오류율을 모니터링**할 방법을 정의한다.
- [ ] 부적합(nonconformity) 발견 시 시정조치를 기록하고 재발 방지책을 반영한다.
