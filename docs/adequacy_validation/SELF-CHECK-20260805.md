## 2. 검증 목적

검증 하니스 자체가 (a) 선언한 통제를 실제로 수행하는가, (b) 그 통제가 실패할
수 있는가(항진명제가 아닌가), (c) 산출물이 선언된 입력만으로 재현되는가를
확인한다.

## 3. 입력 데이터 및 전제

- 외부 데이터 없음. 합성표본(n=100,000, 워크플로우 데모 기본 seed)과 하니스가
  커밋 보관 중인 SSoT JSON 원장을 입력으로 사용했다.
- 실행 환경: Python 3.11.15, `pip install -e .` 후 `python -m vta` 진입점.
- 전제: git rev `29eb424` 트리 기준. 운영계 접속·실 고객 데이터 없음.

### 5.1 음성 통제 (통제가 실패할 수 있는가 — ADV-CALC-06)

독립 재계산에 의도적 오류를 주입해 통제 발현을 확인했다.

- 양성: 주장 0.135 vs 재계산 0.135 → 차이 0.000000, 허용 이내, exit 0
- 음성: 주장 0.145 vs 운영입력 13.5/100 → 재계산 0.135, **차이 -0.010000
  허용오차 초과, exit 1**, 기여도가 implementation -0.010 / data +0.000 으로
  분해되고 합계 대사 PASS

즉 이 경로의 통제는 항진명제가 아니며 실제로 실패한다.

## 6. 이상 징후 및 원인 후보

1. **매니페스트 validated 0건 (163건 중).** 하니스 설계상 promote 는 인간만
   가능하므로 구조적 결과일 수 있으나, "효과가 검증되지 않은 변경은 성공으로
   간주하지 않는다"(CLAUDE.md §4.3)는 자기 규율에 비추면 163건이 전부
   미검증 상태로 누적돼 있다는 뜻이다. 원인 후보: 승인 주체 부재(HITL 대기) /
   promote 워크플로우 미사용.
2. **이월 10건 전건 열림, 최장 10회차 연속 미해소(CO-001, CO-002).** 차단
   사유가 대부분 "실 원장 없이는 판정 불가" 로, 합성표본 환경의 구조적 한계다.
   합성 데이터로 도달 가능한 검증 심도의 상한에 닿아 있다.
3. **패턴 P-DOC 8회 반복 · P-CTRL 5회 반복이 여전히 진행 중(F-E01 열림).**
   문서·주장과 코드 사실의 괴리, 통제 경계 문제가 회차를 넘겨 재발하고 있다.
4. **로그 파생 3개 페이지가 재현 범위 밖(SKIP).** 선언 입력만으로 재현되지
   않으며, 재현하려면 `log_dir` 스냅샷 동반 보존이 필요하다.
5. **VAL-005(독립 평가셋)·VAL-011(Benchmark)·VAL-018(통합 원장) 부분 구현.**
   OOT/OOS 설계 통제·개발자 접근 분리 부재, 벤치마크 유의성 자동 판정 부재,
   상시검증과 독립검증 결과의 단일 원장 미연결 및 반출·보존기간 통제 부재.

## 7. 한계와 리스크

- 본 점검은 **합성표본 기반**이다. 실 운영 데이터에서의 성능·안정성을 보증하지
  않는다.
- 커버리지 91.7% 는 요건 대비 구현 존재 여부이지 **구현 정확성의 보증이 아니다.**
- 규정 원문이 저장소에 없어 인용 474종의 원문 정합성은 미보증(CO-004). 기준선
  등록으로 무단 증가만 차단된다.
- 자기결함 원장 SD-01~SD-06 이 보여주듯 **검증자도 오판한 이력이 있다.** 이번
  점검 역시 3선 자기검증의 대상이며 무오류를 주장하지 않는다.
- `vta trigger evaluate` 의 tolerance 가 다수 항목에서 0.0000 이라 variance 부호만
  판정한다. 임계 설계의 적정성 자체는 이번 점검 범위 밖이다.
