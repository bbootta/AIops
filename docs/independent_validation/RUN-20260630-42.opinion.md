### 5.1 F-C01 (중부적합) — 요청서가 자기 커밋에서 재현되지 않습니다


전 필드 대조 결과 **차이는 가정 [27] 하나**입니다.

```

요청서 "… 수치 토큰 1,260개 중 구간 안은 46개(3.7%) …"
```

`doc_figures.coverage_sentence()`가 대조 대상 문서
(`RUN-20260630-42.remediation.md`)의 토큰을 세는데, 그 문서에 **13차 절이 요청서와
같은 커밋에서 추가**됐습니다. 커밋 단위 실측이 위 §1의 표입니다.

**범위를 좁혀 기록합니다.** 산출값 10종, `headline_digest`(`3b4b6b31…`),
`submission_digest`(`9d0c6fa3…`)는 전부 비트 단위로 재현되므로 **리스크 수치는
무손상**입니다.

그럼에도 중부적합으로 보는 이유는 셋입니다.

1. 게이트가 `request_id`로 요청·응답을 대사하므로 식별자 재현성은 이 교환 체계의

   없습니다 — 그 확인을 12회차까지 매번 "비트 단위 일치"로 보고해 왔습니다.

| 안 | 내용 | 평가 |

| ⓐ | 문서 통계를 요청 식별자 산정에서 제외 | 구조적 |
| ⓑ | 요청서 생성을 모든 문서 편집 **뒤로** 이동 | 절차 의존 — 또 어긋날 수 있음 |
| ⓒ | 문서 통계를 고정 리비전에서 측정 | 가능하나 기준 리비전 관리 부담 |

> 무엇을 지문에 넣을지는 "그것이 산출물인가"가 아니라 **"그것이 산출물보다 먼저
> 확정되는가"**로 정해야 합니다.

산출값과 서식은 요청서보다 먼저 확정되므로 지문에 들어가도 됩니다. 시정 문서는
요청서 **뒤에** 쓰이므로 들어가면 안 됩니다.
