### 5.4 F-A01 (경부적합) — 그 통제가 제출 실행을 덮지 않습니다

```
기준선 (conftest.PINNED_ASOF = 2026-06-11)   290서식  5,844라인
제출본 (asof 2026-06-30)                      290서식  5,896라인
                                                       ────────
제출본에만 있는 라인  52건    기준선에만 있는 라인  0건
```

52건은 전부 **라인명에 날짜가 박힌 일별 항목**입니다.

```
B2316/3010|2026-06-12 트레이딩목적 자산
B2316/3011|2026-06-15 트레이딩목적 자산
   …  (2026-06-30까지 13건)
B2602-2/3010|2026-06-12 LCR
   …
```

이 52건은 삭제돼도 `test_no_form_line_disappears`가 통과합니다.

더 근본적인 문제가 있습니다. 라인명이 날짜를 담으므로 **기준선은 원리적으로 다른
기준일에 적용할 수 없습니다** — `test_added_lines_are_declared`가 어떤 다른
`asof`에서도 52건을 "추가"로 보고 FAIL합니다. 즉 통제를 제출 실행에 돌리는
선택지 자체가 닫혀 있습니다.

같은 함정을 문서 대조에서는 `docs_for_run()`이 "문서는 특정 실행을 설명한다"로
이미 풀었는데, 테스트 계층에서 재발했습니다.

**F-901 원형은 잡힙니다**(BF202는 날짜 무관). 산출값 영향도 없습니다. 시정
방향은 라인명의 날짜를 정규화(`<date>` 치환)해 구조를 `asof` 독립으로 만들고
제출 실행에도 적용하는 것입니다.

### 5.5 F-A02 (경부적합) — 같은 항목의 인용 항이 서식군마다 다릅니다

| 서식군 | 라인 | 인용 |

| 해외 | BF202/4020 · BF405/1030 | 은행업감독규정 제29조 **제1항** 최저적립률 |

대상이므로 **제2항이 맞습니다.**

같은 모듈 안에서도 BF202/4000(감독 최저적립액)과 4020(순차액)이 동일한 `_C29`
상수를 쓰는데, 전자는 제1항이 맞고 후자는 아닙니다.

**신설된 `test_citation_survives_edits`는 "제29조" 포함 여부만 보므로 이 차이를
구분하지 못합니다** — 통제가 한 단계 성깁니다.

이 불일치는 10차 편집 이전부터 존재했고(9차 구조 대조로 확인), **제가 10회에

> 통제가 있다는 것과 통제가 **제출물을 덮는다**는 것은 다릅니다.

갇힙니다.
