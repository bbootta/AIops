### 5.1 F-901 (중부적합) — 시정이 대상 밖을 지웠습니다

`forms_fss_overseas_a._bf202`에서 4020의 `formula`를 고치는 편집이 뒤따르는 두
라인을 함께 삼켰습니다. 산출된 서식에서 실측한 결과:

```
BF202  4000  감독 최저적립액        70,191,573,791.65   제29조 제1항
BF202  4010  IFRS 9 대손충당금      50,856,049,298.81   IFRS 9 5.5
BF202  4020  대손준비금 순차액      19,335,524,492.84   Basel III CRE22 적격 담보·감독 haircut  ← 인용 오류
       (5000 담보평가액 · 5010 담보인정액 없음)
검증: [약정유형별 합, 적격+비적격, 거래유형별 합, 담보인정액 ≤ 담보평가액]
```

| 항목 | 9차 | 10차 |
|---|---:|---:|
| 서식 라인 수 | 5,896 | **5,894** |
| 실측 근거 라인 | 4,002 | **4,000** |

BF202(대차대조표 각주계정)는 `applicable=True`인 **제출대상** 서식입니다.

**통제 상태**: 서식검증 1,735건 실패 0 · 교차 서식 대사 9건 PASS ·
자체검증 PASS 60 FAIL 0 · 테스트 **1,049 passed(9차와 동일)**. 유일하게 반응한 것은 문서 생성 구간

**중부적합으로 보는 이유**는 셋입니다.

1. 제출대상 서식에서 공시 라인 2건이 **소실**됐습니다 — 값이 틀린 것이 아니라
   없어졌습니다.
2. 제출 라인 하나가 **틀린 규정을 인용**합니다(대손준비금에 담보 규정).
3. 시정이 새 결함을 만든 **두 번째** 사례이고, 이번에는 어떤 자동 통제도 잡지
   못했습니다.

판단 근거를 밝히므로 **반증이 있으면 재검증합니다.** 두 라인이 다른 서식에서
대체 공시되거나 `CRE22` 인용이 의도된 것이라면 근거를 제시해 주십시오.

### 5.2 F-902 (적합) — F-802 해소, 주입시험으로 실증

시정은 두 곳을 바꿨습니다.

1. 파이프라인 순서를 **IFRS 9 ECL → 자본**으로 뒤집어 충당금이 자본 단계 전에
   존재하게 함
2. `_stage_capital`에서 `capital = CapitalStack(cet1 = capital.cet1 − shortfall, …)`
   — **실제 자본을 줄임**

3선이 `_stage_capital`을 격리 호출해 IRB EL을 인위로 올렸습니다(충당금
94,531,443,664.95 고정).

| IRB EL | 차감액 | CET1 비율 변화 | BR-02 대사 |
|---:|---:|---:|---|
| 40,237,649,241 (현재) | 0 | — | PASS |
| 120,000,000,000 | 25,468,556,335 | **−0.296%p** | PASS |
| 200,000,000,000 | 105,468,556,335 | **−2.277%p** | PASS |

총자본비율·레버리지비율도 함께 움직입니다(레버리지는 `tier1 = cet1 + at1`이므로

`net == cet1_total` 불변식을 유지하므로 BR-02 "명세 합계 = 자본금액" 대사가 세
시나리오 전부 PASS입니다(차이 3.66e-04, 허용 1.0).

CRE40.30 초과충당금의 보완자본 산입(본 실행 한도 34,411,283,632)을 "may" 규정이라
