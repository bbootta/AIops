## 1. 요약

이번 시정은 **산출 로직을 전혀 건드리지 않았습니다.** headline 10종을 재현해
3차와 전부 일치했고 `headline_digest`도 `edf5c98…`로 동일합니다. 바뀐 것은
게이트·문서·공시뿐이며, 그 주장을 재현으로 확인했습니다.

3차 지적 3건이 모두 해소됐고, **경부적합이 3건 → 1건으로 줄었습니다.**
게이트는 네 라운드 만에 처음으로 `조건부`를 반환합니다.

특기할 것은 2선이 **3선이 지적하지 않은 결함을 스스로 찾았다**는 점입니다.
`request_id = digest(run_id, headline_digest)`라 산출값이 안 바뀌는 시정에서는
식별자가 그대로 나오고, 실제로 3차 응답이 4차 승인으로 통했습니다. 판정 도구를
검증 대상에 넣는 습관이 3선에서 2선으로 옮겨간 결과로 봅니다.

남은 1건은 그 시정이 **아직 완전하지 않다**는 것입니다.

## 5. 주요 결과

`edf5c9899da404df6ae3dc4d6c8e64d9` 동일. "문서·통제·공시만 바꿨다"는 주장이
사실입니다.

### 5.2 게이트 시정 — 통제를 약화시키지 않음

```python
@property
def passes(self) -> bool:      # 변경 없음 — '적합' + 중부적합 0건
    return self.verdict == "적합" and not any(...)

@property
def conditional(self) -> bool: # 신설 — 세 번째 상태
    return self.verdict == "경부적합" and not any(...)
```

`check_gate`가 `조건부`를 별도 상태로 반환하고 `approved`는 여전히 False입니다.
**경부적합이 자동 통과가 되지 않았습니다.** 3선 지적은 "docstring과 구현 중
하나를 고치라"였는데, 2선은 통제를 약화시키지 않는 쪽을 택했습니다.

실행 검증:

| 4차 응답 (`IVR-0DC4055ED5AF`) | **조건부** | 경부적합 1건 — 잔여위험·후속조건·이행기한 기록 필요 |

## 8. 검증 의견 초안

**경부적합.** 중부적합 0건, 산출값 오류 0건, 게이트 통제 약화 없음.
남은 1건은 stale 방어의 잔여 구멍이며 결재를 절대적으로 막을 사안은 아닙니다.

네 라운드에 걸친 추이는 **중부적합 3 → 1 → 0 → 0**, 경부적합 **3 → 2 → 3 → 1**
입니다. 매 라운드 지적을 방어하지 않았고, 2차에서는 결함을 옮겼으나 3차부터는
축소했으며, 이번에는 3선이 보지 못한 결함까지 스스로 찾았습니다.

게이트가 `조건부`를 반환하므로 결재 책임자가 **잔여위험·후속조건·이행기한을
기록하면 결재 가능**합니다. 조건으로 F-301 해소를 다음 실행 전까지로 잡는 것을
권고합니다.
