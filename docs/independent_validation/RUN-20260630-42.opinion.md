### 5.3 F-E01 (경부적합) — 신설한 배선 검사가 자기충족입니다

`test_every_generated_sentence_helper_is_wired`는
`grep -rn 'coverage_report\|coverage_sentence' risk_lib tests` 결과에서 `def`·
`import`를 뺀 줄을 "호출부"로 셉니다. **그 grep 대상에 검사 파일 자신이
포함됩니다.**

반증 실험 — 저장소를 복제해 `coverage_report`의 **실제 호출부를 전부 제거**한 뒤
같은 판정을 돌렸습니다.

```
① 원본                       coverage_report: def 1 · use 4   → 통과
② 실제 호출부 전부 제거        coverage_report: def 1 · use 3   → 여전히 통과
      use 3 의 정체:
        tests/test_assumption_claims.py:59   docstring 의 "`coverage_report()`가 정의만 있고"
        tests/test_assumption_claims.py:64   grep 인자 문자열
        tests/test_assumption_claims.py:67   for fn in ("coverage_report", …)
```

즉 이 검사는 **F-D01의 원인이 그대로 재발해도 통과합니다.** 하필 그 원인을
지키라고 만든 자리이며, F-602(통제력 0인 검증이 쟁점을 지키는 자리에 놓여
있었다)와 같은 구조입니다 — `ADV-CALC-06`의 반증 기준에 정확히 걸립니다.

시정은 셋 중 하나입니다.

| 안 | 내용 | 평가 |
|---|---|---|
| ⓐ | grep에 `--exclude=test_assumption_claims.py` | 간단하나 파일명 의존 |
| ⓑ | `ast`로 호출식(`Call`)만 세기 | **가장 견고** — 주석·문자열이 호출로 세어지지 않음 |
| ⓒ | 검사를 산출 쪽 모듈로 옮김 | 대상에서 자연히 빠짐 |

### 5.4 F-E04 (적합) — 도전 지점 답변: **Pack이 아니라 코드를 지문화하십시오**

**먼저 우려하신 순환을 실증했습니다.** Pack을 생성해 파일 목록(181건)을 보면:

```
07_independent_validation/RUN-20260630-42.request.json
07_independent_validation/val_independent_request.csv
01_datamodel/tables/val_independent_request.csv
```

**Pack이 요청서를 담습니다.** 따라서 Pack 내용을 요청 지문에 넣으면 요청서가 자기
자신을 해시하게 되어 F-C01보다 강한 순환이 됩니다. 우려는 근거가 있습니다.

**그러나 원하는 성질은 Pack을 해시하지 않고 얻을 수 있습니다.** Pack은
`f(코드, 데이터, 서식)`의 결정론적 산출이므로, **코드 리비전을 지문화하면 Pack
내부 변경이 전부 잡힙니다.**

```
risk_lib 트리 해시
  14차          3c5646410be560a4edb4a225b0e5d46648a603d1
  F-D01 시정    28e4ec5e150bf1e0b70d89a19761edba80c9db69   ← 이동
  15차          50e90bcda61b6196f91c8e2cdd85d886f0405b22   ← 이동
```

13차에 세운 원칙과도 맞습니다 — **"지문에는 요청서보다 먼저 확정되는 것만
넣는다."** 코드는 요청서 생성보다 먼저 확정되고 `docs/`는 뒤에 쓰이므로,
**`risk_lib`만** 넣고 `docs/`는 빼면 순환이 없습니다.

구체안: `ValidationRequest`에 `code_digest` 필드를 두고 `risk_lib` 소스의 정규화
해시(파일 경로 + 내용을 정렬해 SHA-256)를 넣습니다 — git에 의존하지 않아
재현됩니다.

**부작용도 함께 적습니다.** 코드가 바뀌면 산출값이 그대로여도 `request_id`가
움직입니다. 이는 **의도된 성질**입니다(F-301 이후 일관되게 "산출값이 안 바뀌는
변경일수록 재검증이 필요하다"). 다만 주석·공백 변경에도 움직이므로 재검증 빈도가
오르는 대가가 있고, **그 판단은 결재선의 몫입니다** — 3선은 순환 없는 설계를
권고할 뿐 도입 여부를 정하지 않습니다 (CLAUDE.md §7).

### 이번 회차의 관찰

14차에 "값을 지키는 통제는 여러 겹으로 쌓았지만 '이렇게 하겠다'는 문장 자체를

주목할 것은 **자기충족이 생긴 방식**입니다 — 검사가 자기 대상 범위 안에 자기를
포함시켰습니다. F-A01(통제가 제출 실행을 안 덮음)과 정확히 반대 방향의 같은

> 통제를 만들 때는 **무엇을 검사하는가**만이 아니라 **검사 대상에 무엇이
> 들어가는가**를 정해야 합니다. 너무 좁으면 제출물을 놓치고, 너무 넓으면 자기를
> 세어 실패할 수 없게 됩니다.
