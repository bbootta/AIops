## F-207 (경부적합 · 선결) — 게이트 코드가 스스로 모순됐다

3선이 이번에 **판정 도구 자체**를 검증 대상에 넣었다. `ValidationResponse.passes`의
docstring은 "경부적합까지는 조건부 통과"라고 약속했으나 구현은
`verdict == "적합"`만 통과시켜, 약속한 조건부 경로가 **코드에 존재하지 않았다**.
`ValidationResponse(verdict="경부적합", findings=[]) → passes = False`.

우리 게이트로 3차 응답을 파싱한 결과가 정확히 그 상태다.

```
status : 부적합        reason : 판정 경부적합
중부적합 : (없음)      경부적합 : F-201 · F-202 · F-207
```

지적이 맞다. 판정 도구가 문서와 어긋나면 그 위의 모든 판정이 흔들린다.

**시정** — 세 번째 상태 `조건부`를 도입했다. docstring만 고쳐 "적합만 통과"로
맞추는 선택지도 있었으나, 그러면 문서 지적 수준의 경부적합 하나가 결재를 영구히
막아 게이트를 우회할 유인이 생긴다. 반대로 자동 통과시키면 사람의 판단이 사라진다.

| 상태 | 조건 | 결재 |
|---|---|---|
| `응답대기` | 응답 파일 없음 | 불가 |
| `부적합` | 중부적합 있음 · 재계산 불일치 · run_id/request_id 불일치 | 불가 |
| **`조건부`** | 경부적합 + 중부적합 0건 + 재계산 전건 일치 | **기록 있을 때만** |
| `적합` | 판정 적합 + 재계산 전건 일치 | 가능 |

`조건부`는 `require(ConditionalApproval(...))`로만 통과하며, 기록은
**잔여위험 · 후속조건 · 이행기한 · 배포 범위 · 결재자**를 모두 요구한다. 하나라도
비면 통과하지 않는다 — fail-closed는 유지된다. 기계가 이 기록을 대신 만들지
않는다.

재계산 불일치 검사를 판정 검사보다 **앞으로** 옮겼다. 어긋난 재계산은 어떤
판정과도 무관하게 부적합이어야 한다.

## F-202 (경부적합) — 자산이 커지면 레버리지 반응성이 다시 소멸한다

**조건 1 — 지문을 요청 객체 전체 직렬화로 전환**

`request_identifier(request)`를 신설했다. `asdict(request)`에서 `request_id`와
`created_at`만 제외하고 canonical JSON(`sort_keys` · 구분자 고정)으로 해시한다.

| **4차 시정** | **요청 전체 (2개 필드만 제외)** | — |

## F-901 — 시정이 대상 밖을 지웠다

산출근거 문자열(F-801)을 고치면서 중복된 `formula` 인자를 지우는 스크립트를
썼는데, 종료 조건을 `'",'`로 끝나는 줄로 잡아 **대상 밖 3줄을 함께 삼켰다.**

```
삭제됨   citation=_C29,                       ← BF202/4020 의 인용
삭제됨   FormLine("5000", "담보평가액", …)
삭제됨   FormLine("5010", "담보인정액", …)
결과     4020(대손준비금)에 _CRE22(담보 규정)가 붙음
```

복원했다 — 라인 5,894 → **5,896**, 인용 제자리, 검증 1,735건 실패 0.

## 왜 아무 통제도 잡지 못했나 — 세 층

**1. 값 기반 검증은 사라진 라인을 원리적으로 못 본다.** 라인이 없으면 대사에도
참여하지 않는다. 서식검증 1,735건 실패 0 · 교차 서식 대사 9건 전부 PASS ·
자체검증 FAIL 0 · 테스트 1,049 passed로 직전 회차와 **건수·결과가 동일**했다.

**2. 울린 통제를 내가 껐다.** 문서 생성 구간 대조가 라인 수 감소(5,896→5,894)를
FAIL로 알렸는데 값을 갱신하는 것으로 끝냈다. 직전 회차에는 같은 통제가
**증가**(4,000→4,002)를 잡았을 때 원인(BR-26 라인 추가)까지 규명했다 — 이번엔
**감소**인데도 묻지 않았다. 감소가 더 위험한 방향인데 반대로 대했다. 3선 지적의
핵심이 여기다.

**3. 편집 방식.** 정규식·줄 단위 스크립트로 코드를 고쳤고 그 루프가 원인이었다.

## 시정 — 구조 회귀 통제 신설

`tests/test_form_structure.py`. 값이 아니라 **구조**(서식 → 라인코드·라인명)를
기준선에 고정하고 라인이 사라지면 실패한다. F-901 원형 주입 시 2건을 정확히
탐지한다. 대손준비금 라인에 제29조가 아닌 인용이 붙는 것도 함께 막는다.

**값 기반 지문으로는 안 된다.** 값은 매 회차 바뀌어 재고정이 필요하고, 재고정하는
순간 사라진 라인도 함께 승인된다 — 그게 이번에 일어난 일이다. 구조는 의도적으로
바꿀 때만 바뀌므로 기준선 갱신이 별도 명령을 요구하고, 그 diff가 커밋에 남는다.
2층(울린 통제를 끄기)이 구조적으로 어려워진다.

## 3선이 도전해야 할 지점

1. **구조 기준선의 사각** — 라인 존재·라인명은 보지만 `formula`·`source_module`

# `IVR-F66464125AEE` — 검증 요청

`IVR-9D5A5DBAE888` 지적 2건(F-A01 · F-A02)을 시정하고, 3선이 §7 한계로 남긴

## F-A01 — 통제가 제출 실행을 덮지 않았다

지적대로다. 기준선을 시험 고정일(2026-06-11)에서 만들었는데 제출 실행
(2026-06-30)에는 52라인이 더 있고, 라인명이 날짜를 담으므로 **어떤 기준일에서도
FAIL**한다. 통제를 제출물에 돌리는 선택지 자체가 닫혀 있었다.

`docs_for_run()`이 문서 계층에서 이미 푼 함정을 **테스트 계층에서 재발**시켰다는
지적이 정확하다 — 같은 교훈을 한 계층에만 적용했다.

**시정** — 날짜를 `<date>`로 정규화하고 그 결과 같아진 연속 라인을 하나로 접었다.
월별 영업일 수가 달라 개수까지 맞출 수는 없다. **두 기준일 구조 차이 0** 확인.

**남는 한계** — 일별 계열 **안에서** 라인 하나가 사라지는 것은 못 잡는다. 루프
생성 라인이라 손으로 쓴 라인 소실(F-901의 실제 양상)보다 위험이 낮다고 보고
절충했다.

## F-A02 — 그리고 내 검사가 한 단계 성겼다

지적대로 최저적립액(제1항)과 순차액(제2항)이 `_C29` 상수를 공유했다. 상수를 갈랐다.

더 중요한 것은 **F-901 시정으로 내가 만든 `test_citation_survives_edits`가
"제29조" 포함만 보아 항의 차이를 구분하지 못했다**는 점이다. 조항까지 보도록
강화하니 같은 유형이 **7건 더** 나왔다 — `B2506`은 항 표기가 없었고 `B2431`은
최저적립 판정에 제2항이 붙어 있었다. 3선 지적 2건 포함 **총 9건** 정정.

통제가 한 단계 성기면 그 한 단계만큼 결함이 산다. 내 검사가 통과한다는 것은
근거가 못 된다 — 그 검사가 무엇을 보는지까지 봐야 한다.

## 인용 전수 점검 — 3선 §7 한계에 대한 답

전수 측정: 라인 5,896 · 인용 있음 5,397(91.5%) · **고유 인용 473종** · 국내 규정
인용 중 항 표기 없음 2,907건 · **조·항 혼용 15건**.

항 표기가 없는 것 자체는 결함이 아니다(조 전체가 적용되면 정당). 문제는 473종을
아무도 통독한 적이 없다는 것이었다. **5,397라인은 통독할 수 없지만 473종은 할 수
있으므로** 기준선에 고정했다. 새 인용이 들어오거나 사라지면 실패하고, 기준선
갱신 diff가 곧 "이 인용을 검토했다"는 기록이 된다.

**하지 않는 것을 명시했다** — 인용이 규정 원문과 맞는지는 검증하지 않는다.
규정 텍스트가 저장소에 없다. 통과가 곧 정확성이 아니다.

조·항 혼용은 단언에서 **증분 탐지**로 되돌렸다. 단언으로 두니 "비고"·"한도금액"
같은 일반 라인명이 대량으로 걸렸는데 서식이 다르면 항이 다른 것이 정당하다.
거짓 경보가 나면 다음 사람이 검사를 끈다고 여러 번 적어 놓고 그것을 만들 뻔했다.

- 요청 페이로드에 서식 내용을 담는 필드가 하나도 없다.
- `submission_digest` 자체가 `form_id·line_code·value·text_value`만 해시해
  인용·라인명·산식이 바뀌어도 불변이다.

**11차 응답으로 결재가 가능한 상태였다** — 그 응답은 F-A01·F-A02를 지적한

F-301과 같은 유형의 **세 번째** 반복이다.

| 시점 | 지문 대상 | 뚫린 것 |

산식·인용·산출모듈·소계여부·근거, 서식명·주기·규정근거 포함), 요청서에
