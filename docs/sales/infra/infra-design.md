## 1. 볼륨 역산

KB02 §1.3 공식:

```
필요 도메인 수 = 목표 일일 발송량 ÷ (도메인당 메일박스 수 × 메일박스당 일일 발송량)
```

입력값 (보수적 기준):
- 목표 일일 콜드 발송: 100~150통 (정상 상태)
- 메일박스당 일일 콜드 발송: 20~30통 (웜업 완료 후, KB02 §1.2 보수 운영 기준)
- 도메인당 메일박스: 2~3개 (설계값 2개: 도메인당 총량 30~50통 관리 기준 준수 목적)

계산:
- 필요 메일박스 수: 150 ÷ 25 = **6개** (범위: 100÷30 ≈ 4개 ~ 150÷20 ≈ 8개)
- 필요 도메인 수: 6 ÷ 2 = **3개** (최소) ~ 8 ÷ 2 = **4개** (권장)

| 구성안 | 도메인 | 메일박스 | 메일박스당 콜드 | 일일 총량 | 도메인당 총량 | 평가 |
|---|---|---|---|---|---|---|
| 최소 | 3 | 6 (2/도메인) | 20~25통 | 120~150 | 40~50통 | 목표 충족. 도메인당 총량 상한(50) 근접, 여유 없음 |
| **권장** | **4** | **8 (2/도메인)** | **15~20통** | **120~160** | **30~40통** | 도메인당 총량 안전권. 1개 도메인 오염 시에도 나머지 3개로 90~120통 유지 가능 |

**권장 구성: 세컨더리 도메인 4개 x 메일박스 2개 = 총 8개 메일박스.**
분산이 곧 안전이다(KB02 §4.3). 같은 150통이라도 8박스 x ~19통이
6박스 x 25통보다 안전하고, 도메인 1개가 서킷브레이커에 걸려도 캠페인
전체가 멈추지 않는다.

## 2. 램프업 스케줄 (웜업 완료 후 콜드 발송 기준)

KB02 §4.2를 8개 메일박스에 적용. 증량은 주 단위, 한 번에 20% 이하.

| 콜드 개시 후 주차 | 메일박스당 일일 콜드 | 팀 전체 일일 콜드 | 비고 |
|---|---|---|---|
| 1주차 | 10통 | **80통** | 백그라운드 웜업 병행 (메일박스당 5~10통) |
| 2주차 | 12~15통 | **96~120통** | 지표 정상 확인 후 증량 |
| 3주차 | 15~18통 | 120~144통 | (참고) |
| 4주차 | 15~20통 | **120~160통** | 정상 상태 도달. 목표 100~150통 충족 |
| 8주차 | 15~20통 유지 | **120~160통 유지** | 상한 고정. 추가 확장 필요 시 신규 도메인을 별도 웜업해 증설 (기존 박스 증량 금지) |

증량 중단 트리거 (하나라도 발생 시 해당 주 증량 보류, KB02 §4.2):
- 반송률 2% 초과 → 리스트 재검증
- 스팸 신고 발생 → 타깃/카피 점검
- 오픈율 급락 (추세 기준) → 볼륨 50% 감축 + 배치 테스트

운영 규칙:
- 시퀀스 후속 터치(2~4통째) 포함 총 발송량으로 상한을 관리한다.
- 발송 간격: 메일 간 랜덤 딜레이 5~15분, 동시 폭주 발송 금지.
- 발송 시간대: 수신자 시간대 기준 평일 업무시간. US 동부(ET)와 UK(BST/GMT)
  분리 스케줄. 화~목 오전이 통계상 우수(업계 통설).

## 4. 도메인 전략

### 4.1 대원칙

- **onelineai.com 루트 도메인으로는 콜드 메일을 절대 보내지 않는다** (KB02 §1.1).
  루트 도메인은 회신 수신, 웹사이트, 거래 메일 전용.
- 세컨더리 도메인이 오염되면 그 도메인만 폐기·교체한다. 이것이 세컨더리의
  존재 이유다.

### 4.2 네이밍 후보 (브랜드 자연 변형, 스팸 어휘 금지)

우선순위 순. 구매 시점에 가용한 것 중 상위 4개를 선택한다.

| 순위 | 후보 | 비고 |
|---|---|---|
| 1 | tryonelineai.com | 동사+브랜드, 하이픈 0 |
| 2 | getonelineai.com | 동사+브랜드, 하이픈 0 |
| 3 | onelineaihq.com | 브랜드+hq, 하이픈 0 |
| 4 | meetonelineai.com | 동사+브랜드, 하이픈 0 |
| 5 | joinonelineai.com | 예비 |
| 6 | onelineai-hq.com | 하이픈 1개 (허용 상한), 위 후보 소진 시만 |
| 7 | onelineai.co | .com 소진 시 대안 TLD |

- **TLD: .com 최우선.** 대안은 .co / .org. 저가 TLD(.xyz, .top, .live 등)
  금지 (KB02 §1.2). .com 대비 대안 TLD 격차는 2~4%p 수준(업계 통설).
- 하이픈 0개 권장, 최대 1개. 2개 이상 금지(인박스 도달 약 18% 하락, 업계 통설).
- offer, deal, promo 등 스팸성 어휘 포함 금지.

### 4.3 리다이렉트와 부대 설정

- 세컨더리 도메인 4개 전부 **https://onelineai.com 으로 301 리다이렉트**
  (루트와 www 모두). 수신자나 보안팀이 도메인을 조회했을 때 실체가 확인돼야
  한다. 금융권 수신자는 발신 도메인을 조회할 확률이 높다.
- WHOIS 프라이버시 활성화(레지스트라 기본 제공 확인).
- 자동 갱신(auto-renew) 활성화: 만료로 인한 도메인 상실은 인프라 전손이다.

## 5. 메일박스 프로바이더와 계정 구성

### 5.1 프로바이더 혼합 (금융권 수신자 특성 반영)

US/UK 금융기관은 Microsoft 계열(Exchange Online) + 보안 이메일 게이트웨이
(Proofpoint, Mimecast 류) 수신 환경 비중이 높다. 특정 필터 편향을 줄이기 위해
발신 인프라를 혼합한다 (KB02 §1.4).

| 도메인 그룹 | 프로바이더 | 도메인 수 | 메일박스 |
|---|---|---|---|
| 그룹 A | Google Workspace (Business Starter) | 2 | 4 |
| 그룹 B | Microsoft 365 (Business Basic) | 2 | 4 |

- 캠페인 배정 시 수신자 도메인의 MX를 확인해 교차 배정(Gmail 수신자에
  Google 발신 편중 회피 등)을 시도하되, 강제 규칙은 아니다.
- "시트 하나 사서 앨리어스로 돌려쓰기" 금지. 메일박스는 각각 정식 사용자
  시트로 생성한다(2025년 이후 계정 어뷰징 단속 강화, KB02 §1.4).

### 5.2 메일박스 계정 구성

| 항목 | 명세 |
|---|---|
| 주소 형식 | 실명형 (예: jjlee@tryonelineai.com, first name 기반). info@, sales@ 같은 role 계정 금지 |
| 명의 | 실제 대응 가능한 인물(PO 본인 + 실존 팀원). 가공 인물 금지 |
| 프로필 | 프로필 사진, 실명, 직함 설정 |
| 서명 | 플레인 텍스트 서명: 이름, 직함, 회사명, 메인 사이트(onelineai.com) 링크 1개. 이미지 배너·다중 링크 금지 |
| 회신 처리 | 답장은 해당 메일박스에서 PO가 직접 처리. 자동 포워딩 설정 시 메인 도메인 수신함으로 |

## 6. DNS 인증 명세와 검증 방법

도메인 4개 각각에 아래 레코드를 게시한다. 값 게시는 PO, 검증 실행과 기록은
deliverability-engineer. 아래 예시의 `<domain>`은 각 세컨더리 도메인.

### 6.1 레코드 명세

**MX** (회신 수신용, 프로바이더별)

| 그룹 | 레코드 |
|---|---|
| Google | `<domain>. MX 1 smtp.google.com.` |
| Microsoft | `<domain>. MX 0 <domain-key>.mail.protection.outlook.com.` (M365 관리센터가 제시하는 값) |

**SPF** (TXT, 루트)

| 그룹 | 값 | 조회 수 |
|---|---|---|
| Google | `v=spf1 include:_spf.google.com ~all` | 3회 (10회 제한 내) |
| Microsoft | `v=spf1 include:spf.protection.outlook.com ~all` | 1~2회 |

- `-all`이 아니라 `~all`(소프트페일)을 쓰고 집행은 DMARC에 맡긴다 (KB02 §2.2).
- 세컨더리 도메인에는 다른 발신 서비스 include를 추가하지 않는다 (조회 10회
  제한 여유 확보 + 발신 경로 단순화).
- SPF TXT 레코드는 도메인당 정확히 1개여야 한다(중복 게시 시 PermError).

**DKIM** (2048bit)

| 그룹 | 방식 |
|---|---|
| Google | Admin Console > Apps > Gmail > Authenticate email에서 **2048bit 키 생성** → TXT `google._domainkey.<domain>` 게시 → 콘솔에서 "Start authentication" 클릭 |
| Microsoft | Defender 포털(security.microsoft.com) > Email authentication settings > DKIM에서 CNAME 2개(`selector1._domainkey`, `selector2._domainkey`) 게시 → Enable 토글 |

- 키 값 붙여넣기 누락이 흔한 실패 원인이므로 게시 후 반드시 검증 도구로 확인.

**DMARC** (TXT, `_dmarc.<domain>`)

시작값:
```
v=DMARC1; p=none; rua=mailto:dmarc-reports@onelineai.com; fo=1
```

단계 상향 스케줄 (rua 리포트에서 정당 발신의 SPF 또는 DKIM 정렬 100% 통과
확인이 상향의 전제):

| 시점 | 정책 | 조건 |
|---|---|---|
| D-28 (게시 시) | `p=none` | 모니터링 전용. Google/Yahoo 최소 요건 충족 |
| 콜드 개시 + 4주 | `p=quarantine; pct=25` | rua 4주치에서 정렬 실패 0건 |
| 콜드 개시 + 6주 | `p=quarantine; pct=100` | pct=25 구간 이상 없음 |
| 콜드 개시 + 10주~ | `p=reject` 검토 | 발신 경로가 발송 도구 1개로 고정돼 있음을 재확인 후. 콜드 전용 도메인은 quarantine 유지도 허용 |

- rua 수신 주소는 메인 도메인 앞으로 받되, XML 수동 파싱 대신 무료 파서
  (Postmark DMARC Digests, EasyDMARC free tier 등)를 연결한다.
- 정렬(alignment): From 도메인 = 세컨더리 도메인 자체이므로 SPF/DKIM 모두
  같은 도메인에서 정렬된다. 발송 도구가 Return-Path를 바꾸는 설정을 쓰지
  않는지 확인한다.

**커스텀 트래킹 도메인** (CNAME)

```
track.<domain>. CNAME <발송 도구가 지정하는 트래킹 호스트>.
```

- 발송 도구(§8)의 공유 트래킹 도메인 사용 금지: 남의 평판을 물려받는다
  (KB02 §5.1). 도구 대시보드에서 도메인별 커스텀 트래킹 도메인을 연결하고
  SSL 발급 완료까지 확인한다.
- 도달이 흔들리면 오픈 트래킹부터 끈다.

**기타**

- Google Postmaster Tools(v2)에 도메인 4개 전부 등록, Compliance Status
  확인 (KB02 §6.2).
- 301 리다이렉트: §4.3.
- PTR/rDNS: Google/Microsoft 호스팅 발신이므로 자체 설정 불요 (자체 SMTP
  전환 시에만 해당).

### 6.2 검증 방법 (도구와 명령)

검증 실행 기록은 인프라 런북에 첨부한다. 도메인 4개 x 아래 전 항목.

| 항목 | 명령/도구 | 통과 기준 |
|---|---|---|
| SPF 게시 | `dig TXT <domain> +short` | v=spf1 레코드 정확히 1개, 값 일치 |
| SPF 조회 수 | MXToolbox SPF Record Lookup (mxtoolbox.com/spf.aspx) | Lookup 수 10 이하, PermError 없음 |
| DKIM (Google) | `dig TXT google._domainkey.<domain> +short` | k=rsa 키 존재, 2048bit (키 길이는 MXToolbox DKIM Lookup으로 확인), 콘솔 상태 Authenticating |
| DKIM (M365) | `dig CNAME selector1._domainkey.<domain> +short` (selector2 동일) | onmicrosoft.com 대상 CNAME 2개, Defender 포털 토글 Enabled |
| DMARC | `dig TXT _dmarc.<domain> +short` | v=DMARC1, p= 값 일치, rua 주소 일치 |
| rua 수신 | 파서 대시보드 | 게시 후 48시간 내 첫 리포트 수신 |
| MX | `dig MX <domain> +short` | 프로바이더 값 일치 |
| 트래킹 CNAME | `dig CNAME track.<domain> +short` | 도구 지정 호스트, https://track.<domain> SSL 유효 |
| 301 리다이렉트 | `curl -sI https://<domain>` | `HTTP 301` + `location: https://onelineai.com` |
| 정렬/종합 | 각 메일박스에서 Gmail 테스트 계정으로 발송 → "원본 보기" | SPF=PASS, DKIM=PASS, DMARC=PASS 전부 확인 |
| 스팸 점수 | mail-tester.com (실제 캠페인과 동일 카피·트래킹 조건) | 10/10 |
| Postmaster | postmaster.google.com | 도메인 4개 등록 + 소유권 확인 완료, Compliance Status 녹색 |

## 7. 웜업 계획

### 7.1 방식

- 발송 도구 내장 웜업(실 메일박스 P2P 네트워크형)을 기본으로 한다.
  봇/헤드리스 기반 가짜 참여형 도구 금지 (KB02 §3.3).
- 기간: **3주 표준, 여유 시 4주.** 2주 미만으로 콜드 개시 금지.
- 웜업 설정값: 답장률 30~40% (90~100%는 봇 패턴으로 역탐지), 일일 한도는
  아래 일정표, 주말 발송 축소 옵션 활성화.

### 7.2 주차별 일정 (메일박스 1개 기준, 8개 동일 적용)

| 주차 | 일일 웜업 발송 | 목표 지표 |
|---|---|---|
| 웜업 1주 (D-24~) | 5 → 10통 | 답장률 30%+ |
| 웜업 2주 | 10 → 20통 | 매주 5~10통씩 증량, 인박스율 90%+ |
| 웜업 3주 | 20 → 30통 | 답장률 40~50%, 반송률 2% 미만, 인박스율 90%+ |
| (선택) 4주 | 30~40통 | 지표 정상 유지 확인 |

### 7.3 콜드 개시 판정 기준 (전건 충족)

- 웜업 메일 인박스율 **90% 이상** (80~90%는 경고, 80% 미만이면 개시 금지 +
  볼륨 절반 감축 후 회복 대기, KB02 §3.3/§6.1)
- 웜업 답장률 30~40% 유지
- 반송·스팸함 착지 이상 없음
- 웜업 기간 3주(최소 2주) 경과

### 7.4 상시 백그라운드 웜업

- 콜드 개시 후에도 웜업을 끄지 않는다. 메일박스당 일 5~10통(또는 총 발송량의
  20~40%) 상시 유지 (KB02 §3.2).
- 콜드 + 웜업 합산 총량이 메일박스당 일 50통을 넘지 않게 관리한다.
- 주간 점검 항목에 "웜업 백그라운드 가동 상태" 포함 (런북 §4.2).

## 8. 발송 도구 안전장치 4종 설정 명세와 검증 [G5][G6]

발송 도구는 커스텀 트래킹 도메인, 랜덤 딜레이, 메일박스 로테이션, 내장 웜업,
바운스 자동 처리, 임계 기반 자동 중단을 갖춘 콜드 아웃리치 전용 플랫폼
(Instantly, Smartlead 급)이어야 한다. 일반 뉴스레터 도구(Mailchimp 류) 금지.

설정 적용: PO. 적용 검증: deliverability-engineer. **4종 중 하나라도 미검증이면
인프라 미완료 판정이며 발송 스케줄을 배정하지 않는다 [G5]. #4 미설정은
캠페인 착수 불가 사유다 [G6].**

| # | 안전장치 | 설정 명세 | 검증 방법 |
|---|---|---|---|
| 1 | 답장 시 시퀀스 자동 중단 | 답장(긍정·부정 불문) 수신 즉시 해당 수신자의 모든 후속 터치 자동 중단. "Stop on reply" 류 옵션을 캠페인 기본값으로. 스레드 전체(같은 회사 다른 시퀀스는 별도 판단) | 기능 테스트: 테스트 수신자로 시퀀스 투입 → 터치 1 수신 후 답장 → 도구에서 해당 수신자 상태가 replied/paused로 전환되고 터치 2가 발송되지 않음을 확인. 설정 화면 스크린샷 보존 |
| 2 | 하드바운스 자동 suppression | 하드바운스 발생 즉시 도구 블록리스트 등록 + 전 캠페인 시퀀스 제외. 재발송 영구 차단 | 기능 테스트: 자사 통제 도메인의 존재하지 않는 주소 1건을 테스트 캠페인에 투입 → 550 반송 후 도구 블록리스트에 자동 등재 확인. 설정 화면 스크린샷 보존 |
| 3 | 마스터 suppression 양방향 동기화 | 마스터 suppression 리스트(sales-compliance-officer 관리)와 도구 블록리스트 간 양방향 동기화. 주기: 최소 일 1회 + 매 터치 릴리스 직전 수동 대조 [G2]. 수신거부·신고·바운스는 주소 단위가 아니라 인물/회사 단위로 전파 | 대조 테스트: 마스터 리스트에 테스트 항목 추가 → 동기화 주기 내 도구 블록리스트 반영 확인. 역방향: 도구에서 수신거부 발생 항목이 마스터에 반영되는지 확인. 터치 릴리스 시 delta 대조 기록 |
| 4 | 임계 초과 자동 발송 중단 | 도구 네이티브 규칙으로 캠페인 자동 일시정지 설정: 바운스율 2% 초과 시 즉시, (도구 지원 시) 스팸 신고 감지 시 즉시. 추가 방어: 메일박스당 일일 한도 하드캡(§2 램프업 값), 발송 간격 랜덤 딜레이 5~15분 | 설정 검증: 임계값 입력 화면 스크린샷 + 설정값이 본 명세와 일치하는지 대조. 도구가 신고율 자동 중단을 미지원하면 대체 통제(일간 점검에서 수동 판정, 런북 §5.3)를 명기하고 그 갭을 인프라 런북에 기록. 발동 이력 발생 시 실제 작동 여부를 사후 확인 [G6] |

공통 검증 규칙:
- 검증은 4개 도메인 그룹 전체 계정에 대해 수행하고, 결과(항목, 일시, 증빙)를
  인프라 런북 §3 표에 기록한다.
- 도구 교체나 설정 변경 시 4종 전체 재검증.

## 10. 인프라 완료 판정 조건 (전건 충족 시 완료)

1. 도메인 4개 구매 + 301 리다이렉트 + WHOIS 프라이버시 + 자동 갱신 (§4)
2. 메일박스 8개 생성, 실명형 주소·프로필·서명 완료 (§5)
3. DNS 검증 전 항목 통과: 도메인 4개 x §6.2 체크리스트, 검증 실행 기록 보존
4. Google Postmaster Tools 4개 도메인 등록, Compliance Status 녹색
5. 웜업 3주(최소 2주) 완료 + §7.3 지표 기준 충족 + 백그라운드 웜업 유지 설정
6. 발송 도구 안전장치 4종 설정 검증 완료 (§8) [G5][G6]
7. mail-tester 10/10 + 인박스 배치 테스트 85%+ (실 캠페인과 동일 조건)
8. 인프라 런북(deliverability-runbook 포맷) 작성 + PO 서명

캠페인별 프리플라이트(리스트 검증, suppression 대조 등)는 G5에 따라 캠페인
워크플로에서 별도 수행한다.
