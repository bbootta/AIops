# 호프: 마지막 거리 — Unreal Engine

영화 **호프**의 시가전 장면을 언리얼 엔진으로 옮긴 3인칭 슈팅게임입니다.
같은 저장소의 `hope-shooter/`(three.js + Electron)와 같은 게임이고, 렌더러만 다릅니다.

> **이 프로젝트는 컴파일된 적도, 실행된 적도 없습니다.** 만든 환경에 언리얼 엔진이
> 없었고 설치할 수도 없었습니다. 아래 [검증하지 못한 것](#검증하지-못한-것)을
> 먼저 읽어 주세요.

---

## 왜 언리얼인가

`hope-shooter/`의 WebGL 빌드는 실사화를 계속 밀어붙인 끝에 브라우저가 넘을 수 없는
천장에 닿았습니다. 언리얼로 옮기면서 실제로 달라지는 것은 이 네 가지입니다.

| WebGL 빌드에서 했던 것 | 언리얼에서 대체되는 것 |
| --- | --- |
| PMREM으로 미리 구운 HDRI 환경광 (빛이 튀지 않음) | **Lumen** — 실시간 GI. 햇빛이 파사드에 튕겨 상점 안쪽과 차양 아래로 실제로 들어감 |
| 캐스케이드 섀도우 맵 (근거리에서 계단현상) | **Virtual Shadow Maps** — 접촉 그림자 해상도가 자릿수로 올라감 |
| 빌보드 안개 카드 (AO 패스를 망가뜨렸던 그 카드) | **Volumetric Fog** — 빛을 실제로 산란시키는 참여 매질 |
| 폴리곤 예산에 묶인 절차적 지오메트리 | **Nanite** — 스캔 에셋을 예산 없이 그대로 투입 |

## 실사화는 실제로 어디에서 오는가

**이 저장소의 코드만으로는 실사가 아닙니다.** 거리와 인물의 형태는 엔진 기본 큐브로
조립된 플레이스홀더입니다. 스캔 에셋은 Epic 계정이 필요하고 라이선스상 저장소에 담을
수 없어 **제가 대신 넣어 드릴 수 없습니다.** 대신 넣는 과정을 스크립트로 만들어
두었습니다 — 수동 작업이 아니라 명령 한 줄입니다.

### 1. 환경 표면 — Fab / Quixel Megascans

```
에디터 > Window > Fab 에서 원하는 Surface들을 소스 파일로 다운로드
Tools/import_megascans.py 상단의 SOURCE_ROOT 와 ASSIGNMENTS 를 편집
Output Log > Python:
exec(open(r"<프로젝트경로>/Tools/import_megascans.py").read())
```

스크립트가 텍스처를 임포트하고, **압축 설정을 올바르게 잡은 뒤**, `MI_Hope_*`
인스턴스에 연결합니다. 압축 설정은 장식이 아닙니다 — 노멀맵이 컬러 텍스처로
들어오면 sRGB 인코딩과 BC1 압축을 거치면서 "스캔처럼 보이게 하는" 미세 굴곡이 뭉갭니다.
맵은 남고 디테일만 사라지므로 눈치채기도 어렵습니다. ORD 맵도 마찬가지로 sRGB로
읽히면 러프니스가 감마 곡선을 타서 모든 표면이 과하게 번들거립니다.

스크립트는 스캔 알베도를 넣을 때 플레이스홀더 틴트를 흰색으로 되돌립니다. 안 그러면
스캔 색상에 틴트가 한 번 더 곱해져서 새까맣게 됩니다.

### 2. 인물 — MetaHuman

MetaHuman(또는 아무 스켈레탈 메시)을 아래 경로에 두면 **코드 수정 없이** 각진
경찰관을 대체합니다.

```
/Game/Characters/Officer/SK_Officer     스켈레탈 메시
/Game/Characters/Officer/ABP_Officer    애님 블루프린트 (선택)
```

`hand_r` 소켓이 있으면 소총이 자동으로 오른손에 붙습니다.
**단, 메시 교체는 쉬운 절반입니다** — 애님 블루프린트가 없으면 레퍼런스 포즈로 굳은
채 미끄러집니다. 애니메이션은 별도 작업이고, 이 코드가 대신해 주지 않습니다.

### 3. 거리 소품

Nanite가 켜져 있으므로 Fab의 스캔 기반 차량·잔해를 폴리곤 감축 없이 그대로 넣으면
됩니다.

## 표면 처리 방식

`build_content.py`는 표면마다 재질을 만들지 않고, **마스터 머티리얼 하나 +
표면별 인스턴스**를 만듭니다. Megascans 임포트가 하는 일이 이 인스턴스의 텍스처
파라미터를 채우는 것뿐이 되도록 하기 위해서입니다.

투영은 **트라이플래너(WorldAlignedTexture)** 입니다. 거리가 엔진 큐브로 조립돼
있는데 큐브 UV는 면마다 0-1이라, 일반 UV로 벽돌을 깔면 타일 하나가 15m 파사드에
늘어납니다. 월드 공간에서 투영하면 타일 크기를 cm 단위로 지정할 수 있고, 어떤 상자에
발라도 동일하게 나옵니다. 벽돌 120cm, 아스팔트 250cm 식으로 실제 치수를 넣어 뒀습니다.

텍스처 파라미터의 기본값은 흰색과 평평한 노멀입니다. 그래서 텍스처가 없으면 틴트만
남은 단색으로, 있으면 스캔 그대로 나옵니다 — 분기도 스위치도 없는 하나의 그래프입니다.

## 조명과 카메라는 실제 물리량입니다

밝기 다이얼을 돌려 맞춘 값이 아닙니다.

- **태양: 32,000 lux.** 맑은 정오가 약 100,000 lux이고, 이 장면은 먼지를 통과한
  낮은 해라 그 3분의 1 정도입니다.
- **카메라: Super 35 센서, f/8, 1/250초, ISO 100.** 검산하면 — 18% 그레이카드의
  휘도는 `32000 × 0.18 / π ≈ 1830 cd/m²`, 필요한 `EV100 = log2(1830 × 100 / 12.5)
  = 13.8`. 카메라 쪽은 `log2(8² × 250) = 14.0`. 6분의 1스톱 이내로 맞으므로 보정값
  없이 정상 노출이 나옵니다.
- **렌즈: 조준 안 할 때 18mm, 조준 시 40mm.** 시야각을 임의로 보간하는 대신 실제
  렌즈를 바꿉니다.
- **포커스는 조준선을 따라갑니다.** 매 프레임 트레이스한 거리로 초점을 잡아, 먼
  블록 끝이 흐려집니다.

태양 밝기를 바꾸면 카메라 노출도 함께 바꿔야 합니다. 둘은 한 쌍입니다.
화면이 너무 밝거나 어두우면 손댈 곳은 `HopeStreet.cpp`의 `AutoExposureBias` 하나입니다.

## 실행 방법

**필요한 것:** 언리얼 엔진 5.4 이상, 그리고 C++ 툴체인
(Windows: Visual Studio 2022 + "Game development with C++" 워크로드 /
macOS: Xcode / Linux: 엔진에 포함된 clang 툴체인).

```
1. HopeLastStreet.uproject 를 더블클릭 → 엔진 버전 선택 → "지금 빌드" 수락
2. 에디터가 열리면 Play (Alt+P)
```

`.uproject`의 `EngineAssociation`은 비워 두었습니다. 설치된 엔진을 직접 고르게 하는
편이 특정 버전에 고정하는 것보다 안전하기 때문입니다.

**콘텐츠 생성 스크립트.** 안 돌려도 게임은 돌아갑니다 — 재질을 못 찾으면 엔진 기본
재질에 색만 입혀 대체합니다. 다만 스캔 재질을 붙이려면 이걸 먼저 돌려야 합니다.

```
에디터 > Output Log > 좌하단 드롭다운을 "Python"으로 변경 후:
exec(open(r"<프로젝트경로>/Tools/build_content.py").read())
```

**조작:** `WASD` 이동 · `마우스` 조준 · `좌클릭` 사격 · `우클릭` 정조준 ·
`R` 재장전 · `Shift` 달리기 · `Space` 재투입

## 구조

```
Config/DefaultEngine.ini        Lumen · Nanite · VSM · TSR · 볼류메트릭 — 렌더러 설정 전부
Config/DefaultInput.ini         입력 매핑
Source/HopeLastStreet/
  HopeBlocks.*                  엔진 프리미티브로 액터를 조립하는 헬퍼 + 재질 폴백
  HopeStreet.*                  거리 지오메트리 + 태양/하늘/안개/포스트프로세스
  HopeCharacter.*               경찰관 — 3인칭 카메라, 오른손 파지, 사격/재장전/반동
  HopeShadow.*                  그림자 괴물 — 추적, 피격, 소멸
  HopeGameMode.*                웨이브 디렉터, 점수, 보급
  HopeHUD.*                     캔버스 HUD
Tools/build_content.py          마스터 머티리얼 + 표면별 인스턴스 + 빈 레벨
Tools/import_megascans.py       스캔 재질 임포트 및 연결 — 실사화의 실제 단계
```

### 설계상 택한 것들

- **레벨 에셋이 비어 있습니다.** 거리는 `AHopeStreet`이 `BeginPlay`에서 직접
  세웁니다. `.umap`·`.uasset`은 바이너리라 에디터 밖에서 만들 수 없는데, 그러면
  clone 직후 실행이 불가능해집니다. 대신 런타임 생성 컴포넌트는 `Static`이 될 수
  없어 Lumen 비용을 더 냅니다 — 프로파일에 잡히면 에디터에서 거리를 굽는 것이 답입니다.
- **Enhanced Input이 아니라 레거시 입력 매핑.** Enhanced Input은 `UInputAction`
  에셋을 요구하고, 그건 다시 바이너리 에셋 문제로 돌아갑니다.
- **UMG가 아니라 캔버스 HUD.** 같은 이유입니다.
- **HUD 문구가 영문.** 엔진 기본 폰트에 한글 글리프가 없어 한글은 네모로 나옵니다.
  한글 HUD를 원하시면 한글 폰트 에셋을 추가하고 `HopeHUD.cpp`의 `GEngine->GetLargeFont()`
  자리를 교체하세요.
- **그림자 괴물이 `ACharacter`가 아닙니다.** 평평한 거리를 플레이어에게 직진하는 게
  전부라, 무브먼트 컴포넌트·AI 컨트롤러·내브메시가 전부 불필요합니다.
- **처치 보상을 픽업 액터 대신 즉시 지급.** 드롭 확률(탄약 34%, 치료 16%)은
  WebGL 빌드와 같습니다.

게임플레이 수치 — 탄창 30발, 재장전 1.7초, 웨이브당 적 수 `4 + 웨이브×2`, 3웨이브부터
20% 확률의 브루트, 헤드샷 3배 — 는 WebGL 빌드에서 그대로 옮겼습니다.

## 검증하지 못한 것

만든 환경에는 언리얼 엔진이 없고, 설치도 불가능했습니다. 근거는 이렇습니다.

- 가용 디스크 **29GB**. UE 5 바이너리 설치만 110GB 이상입니다.
- UnrealBuildTool이 요구하는 **.NET SDK가 없습니다**.
- 엔진 소스는 Epic 계정 연동이 필요한 비공개 저장소로, 이 작업 세션의 접근 범위 밖입니다.

따라서 **다음은 전부 확인되지 않았습니다.**

- 컴파일 여부 — C++ 한 줄도 컴파일해 보지 못했습니다. 오래 안정적인 API만 골라
  썼지만, 그건 근거가 아니라 위험을 줄인 것뿐입니다. 엔진 버전에 따라
  `FPostProcessSettings`의 필드명이나 `ASkyAtmosphere`의 헤더 위치가 다를 수 있습니다.
- 실행·렌더링 여부 — 스크린샷이 없습니다.
- **노출 계산이 화면에서 맞는지.** 산술은 위에 적어 뒀고 검산도 맞지만, 그건 종이
  위의 이야기입니다. `AutoExposureApplyPhysicalCameraExposure`가 기대대로 동작하는지는
  확인하지 못했습니다. 화면이 새하얗거나 새까맣게 나오면 이 조합이 원인일 가능성이
  가장 높고, `AutoExposureBias`로 보정하시면 됩니다.
- **두 Python 스크립트 전부.** 특히 `WorldAlignedTexture`의 입력·출력 핀 이름
  (`"TextureObject (T2d)"`, `"XYZ Texture"`)은 기억에 의존해 적은 문자열이고,
  틀리면 마스터 머티리얼 생성이 실패합니다. 실패해도 게임은 폴백 재질로 돌아갑니다.
- **Megascans 파일명 매칭.** `import_megascans.py`의 `MAP_PATTERNS`는 Megascans의
  일반적인 명명 규칙을 가정한 것이라, 다운로드한 세트의 파일명이 다르면 못 찾습니다.
  Output Log에 어떤 맵을 붙였는지 찍히니 확인하고 패턴을 고치시면 됩니다.
- 프레임레이트. Lumen 하드웨어 레이트레이싱 + VSM은 무거운 조합이라, 사양에 따라
  `DefaultEngine.ini`에서 `r.Lumen.HardwareRayTracing=0`으로 내려야 할 수 있습니다.

첫 빌드에서 에러가 나면 그건 예상 범위 안입니다. 오류를 보내 주시면 고치겠습니다.
