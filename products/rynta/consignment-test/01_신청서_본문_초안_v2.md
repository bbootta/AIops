## 4. 서비스의 명칭 및 주요 신청 내용

### ① 해당 금융서비스의 명칭

**금융회사 리스크모형 검증업무를 위한, 결정론 계산엔진 기반 AI 에이전트 검증·증빙 자동화 서비스**

가이드는 서비스명에 **서비스 대상 + 사용 기술 + 서비스 수단**이 드러나야 한다고 명시하며, "나노페이·FING" 같은 **브랜드명 단독은 나쁜 예시**로 들고 있습니다. 따라서 위 문장형 명칭을 권하고, RYNTA RiskOps는 본문에서 제품명으로만 언급합니다.

**대안** — "금융회사 리스크모형의 정합성 검증과 감사증빙을 자동화하는 AI 에이전트 서비스"

### ② 해당 금융서비스의 종류, 내용 등 업무 범위 : **❻데이터** \[확인필요: 종류 선택\]

**종류 선택 검토** — 선택지는 ❶대출 ❷은행 ❸자본시장 ❹보험 ❺여신전문 **❻데이터** ❼전자금융/보안 ❽P2P ❾기타. RYNTA는 금융회사의 리스크 데이터·모형을 다루므로 **❻데이터**가 가장 근접합니다. 은행 특화를 강조하려면 ❷은행, 정체성을 분명히 하려면 **❾기타(리스크관리)** 도 선택지입니다. 대표님 판단 필요.

**(기획 배경)**

- 금융회사의 리스크모형 검증·감리 업무는 규정상 정기 수행 의무가 있으나, 정량 재계산과 문서 작성이 담당자 개인의 스크립트와 PC에 의존하고 있음
- 감독당국·외부감사가 근거를 요구하면 자료를 다시 수집해야 하고, 담당자가 바뀌면 절차가 조직에 남지 않음
- 한편 범용 생성형 AI를 그대로 적용하면 **수치 환각과 재현 불가** 문제로 금융회사 리스크 부서가 도입을 주저함

**(서비스 내용)**

RYNTA RiskOps는 **계산·정리·판단의 책임을 분리**한 리스크 업무 자동화 플랫폼입니다.

| 계층 | 담당 주체 | 이유 |
| :-: | :-: | :-: |
| 계산 | **결정론(Deterministic) 계산엔진** — 생성형 AI 미사용 | 같은 입력 → 항상 같은 출력. 독립 재계산·검증 가능 |
| 정리·초안 | **AI 에이전트 (AVI·ARI)** | 근거 수집, 문서 초안, 미비사항 목록 자동 생성 |
| 판단 | **사람 + 4-Eyes(2인 교차확인) 승인** | 승인 없이는 어떤 산출물도 확정되지 않음 |
| 기록 | **Evidence Ledger(증빙 원장)** | 입력·버전·판정·승인 이력 불변 기록 |

**(서비스 범위)** — 리스크모형 검증 1사이클 전 과정

1. **데이터 준비상태 점검** — 결측·기간·정합성 자동 진단 (Harness Check)
2. **정량지표 독립 재계산** — 결정론 엔진이 AR·KS·PSI, 부도율 예측 대비 실적, ΔEVE·ΔNII 등을 표준 로직으로 산출
3. **정책 판정** — 내규·감독규정 임계치와 대조하여 적합/조건부/부적합 판정 (Policy Harness)
4. **증빙 수집 및 문서 초안 생성** — 검증의견서 초안, 검증 점검표, 미비사항 목록 (AVI)
5. **자체 정합성 점검** — 에이전트 Self-Validation
6. **4-Eyes 승인** — 작성자·검토자 분리 승인으로 산출물 확정
7. **감사추적 보관** — 재현 패키지 형태로 Evidence Ledger 저장

**(약어 설명)** \[확인필요: 사내 공식 영문 표기 대조\]

| 약어 | 풀이 | 역할 |
| :-: | :-: | :-: |
| AVI | Artificial Validation Agent | 모형검증 에이전트. Hub/Child 구조, 역할경계·증빙·감사추적·Human Review·Fail-safe 규칙 내장 |
| ARI | Artificial Risk Intelligence | 리스크 인텔리전스 에이전트. 리스크 리포트, 이상징후 탐지. AML·STR 확장 검토 중 |
| QV Engine | Quantitative Validation Engine | 정량검증 계산엔진. FastAPI 기반 REST API로 계산과 정책 해석을 분리 |

### ③ 해당 금융서비스 이용자의 범위 등 업무 대상

- **1차 이용자**: 위탁 금융회사의 **리스크관리부·모형검증(감리)부·준법감시 부서 실무자 및 승인권자**
- **2차 수혜자**: 해당 금융회사의 **여신·수신 고객** (모형 품질 향상에 따른 신용평가 정확도·공정성 개선의 간접 수혜)
- 위탁테스트 단계 이용자 규모: 10번 문항 참조

### ④ 해당 금융서비스의 업무 방법

**■ (1단계) 환경 구축 및 데이터 연계** — 금융회사 내부망에 RYNTA 배포, 계정·권한 설정, 검증 대상 모형의 원장 데이터 연계. **데이터는 금융회사 밖으로 반출되지 않으며, 당사는 원본 데이터를 보유하지 않음**

**■ (2단계) 기준선 대사** — 금융회사가 기존 수기 방식으로 산출한 값과 RYNTA 산출값을 **전 항목 대사하여 오차 0 확인**. 이 단계를 통과하지 못하면 다음 단계로 진행하지 않음

**■ (3단계) 병행 운영(Parallel Run)** — 기존 수기 검증 절차를 유지한 채 RYNTA를 병행 운영. 실제 검증 사이클을 수행하고 4-Eyes 승인 절차를 적용

**■ (4단계) 성과 측정 및 보고** — 정확성·효율성·재현성·통제 준수율을 공동 측정하고 성과보고서 작성

### ⑤ 그 밖의 내용

- 본 서비스는 **신규 규제 특례를 필요로 하지 않으며**, 현행 법령 내에서 금융회사 내부 업무 지원 도구로 즉시 운용 가능합니다.
- 금융소비자와 직접 접점이 없는 **금융회사 내부 리스크관리 업무**를 대상으로 하므로 소비자 직접 피해 가능성이 구조적으로 낮습니다.

## 5. 서비스의 혁신성에 관한 사항

가이드 지침 — **비전문가도 이해할 수 있게** 서술하고, **워크플로우 이미지·표 등 시각물을 적극 활용**할 것. → 본 문항에는 4번의 7단계 처리 흐름을 **도식 이미지로 제작하여 삽입**하시기를 권합니다. \[작업필요: 워크플로우 다이어그램\]

### 1. 기술의 혁신성

- **생성형 AI가 수치를 만들지 않는 구조** — 금융권 AI 도입의 최대 장애물인 환각·재현불가 문제를, "숫자는 결정론 엔진, 문장은 에이전트, 판단은 사람"이라는 계층 분리로 구조적으로 차단
- **4-Eyes 승인의 시스템 내장** — 통제 절차를 운영 관행이 아니라 **시스템이 강제**. 승인 없이는 산출물이 확정되지 않음
- **Evidence Ledger** — 입력 데이터, 계산 버전, 판정 근거, 승인 이력을 수행 시점에 자동 축적하여 **재현 패키지**로 즉시 제출 가능

### 2. 아이디어의 혁신성과 기존 금융서비스와의 차별점

| 구분 | As-is (현행 실무) | To-be (RYNTA 적용 후) |
| :-: | :-: | :-: |
| 정량 재계산 | 담당자별 스크립트, 산출 방식 편차 존재 | 표준 계산엔진 API로 단일 로직 재계산 |
| 재현성 | 개인 PC의 코드·중간파일에 의존 | Evidence Ledger에 불변 기록 |
| 증빙 수집 | 검증 완료 후 사후 취합 | 절차 수행과 동시에 자동 축적 |
| 검증의견서 | 전량 수기 작성 | 근거 링크 포함 초안 자동 생성 → 사람이 확정 |
| 통제 | 팀 내부 관행에 의존 | 4-Eyes 승인 시스템 강제 |
| 감독 대응 | 요구 시점에 자료 재수집 | 재현 패키지 즉시 제출 |
| 소요기간(모형 1개) | 2~4주 | 목표 5~10영업일 \[제안값\] |

**경쟁 대안 대비**

| 대안 | 한계 | RYNTA의 차별점 |
| :-: | :-: | :-: |
| 범용 LLM 챗봇 | 수치 환각, 재현 불가, 감사추적 부재 | 수치는 LLM이 산출하지 않음 |
| 기존 리스크 솔루션 패키지 | 계산은 하지만 검증절차·증빙·승인 흐름은 별도 수기 | 계산–판정–증빙–승인을 하나의 흐름으로 통합 |
| 컨설팅 아웃소싱 | 반복 시 비용 누적, 내부 역량 미축적 | 절차가 시스템에 남아 조직 자산으로 축적 |

### 3. 사회적 가치 창출 효과

- 리스크모형 품질 향상 → **신용평가의 정확성·일관성 개선** → 부당하게 낮은 등급을 받는 차주 감소
- 감사추적 체계화 → 금융회사 내부통제 신뢰도 제고 → **금융시스템 안정성 기여**

### 4. 시장 변화 파급효과

- 국내 금융권 **모형 리스크관리 실무의 표준화**에 기여
- 금융 도메인 특화 AI 에이전트의 **국내 레퍼런스 확보** — 해외 솔루션 의존도 완화

## 6. 소비자의 편익에 관한 사항

**가이드 해석 활용** — 작성가이드는 *"금융소비자가 반드시 개인을 의미하지는 않음. 기업을 상대로 서비스 하는 경우, **법인도 금융소비자**라는 광의적 의미로 해석 가능"* 이라고 명시합니다. B2B 서비스인 RYNTA에 유리한 근거이므로 **이 해석을 본문에 명시적으로 원용**합니다.

### ■ 금융소비자(법인 = 위탁 금융회사)의 편익

1. **반복업무 해소** — 정량 재계산·문서 작성 반복 업무가 자동화되어 검증 인력이 **판단·해석 업무에 재배치**
2. **감독 대응 부담 경감** — 외부감사·감독당국의 근거 요구에 재현 패키지로 즉시 대응
3. **업무 연속성 확보** — 담당자 변경·퇴사 시에도 절차와 근거가 조직에 남음
4. **비용 절감** — 외부 컨설팅 의존도 감소

### ■ 금융소비자(개인)의 간접 편익

1. **신용평가의 정확성·공정성 개선** — 모형 성능 저하가 조기에 탐지되어 부당한 등급 산정 위험 감소
2. **금융범죄 피해 예방** — ARI의 AML·STR 확장 적용 시 이상거래 탐지 정밀도 향상

### ■ 사회적 측면

- 금융회사 내부통제의 실효성 제고를 통한 금융시스템 신뢰도 개선

## 7. 현행 법령·규정 등에 따라 허용되는 것인지 여부

**결론 — 본 서비스는 현행 법령상 허용되며, 신규 규제 특례를 필요로 하지 않습니다.** 금융회사가 자사 내부 리스크관리 업무를 지원받기 위해 도입하는 소프트웨어이며, 최종 판단 권한과 책임은 금융회사에 유지됩니다.

## 8. 위탁테스트 진행의 목표 및 필요성, 테스트 운영 시나리오

**※ 심사 중요항목** — 정성적·정량적 목표, 준비 상황, 예상 소요기간, 선정 후 **월별(M+1~M+6) 준비계획**을 반드시 포함해야 합니다.

### ■ 목표 및 기대효과

**□ 정성적 목표**

- 금융회사 리스크모형 검증 업무에서 **"AI가 판단을 대신하지 않으면서도 실무 부담을 줄이는"** 운영 모델이 실제 금융 환경에서 작동함을 실증
- 검증 산출물의 재현성과 감사추적이 감독 대응 수준을 충족하는지 금융회사 내부통제 관점에서 검증

**□ 정량적 목표** \[제안값 — 사내 검토 후 확정\]

| 지표 | 목표 | 측정 주체 |
| :-: | :-: | :-: |
| 기존 수기 산출값 대비 정합성 오차 | **0건** | 위탁 금융회사 검증 담당자 |
| 모형 1개당 검증 소요일 | 기존 대비 **50% 이상 단축** | 공동 측정 |
| 감사추적 완결률 (Evidence Ledger 기록 항목 / 필수 항목) | **100%** | 금융회사 감사 부서 |
| 4-Eyes 승인 미준수 건수 | **0건** | 시스템 로그 |
| 담당자 만족도 | 5점 만점 **4점 이상** | 종료 시 설문 |

**정확성 지표의 독립성** — 오차 0 판정은 당사 산출값이 아니라 **금융회사가 기존 방식으로 산출한 값을 기준**으로 금융회사 담당자가 대사합니다. 심사위원에게 이 점을 명시하는 것이 신뢰 확보에 유리합니다.

### ■ 위탁테스트의 필요성

1. **실데이터 검증 없이는 제품 완성이 불가** — 리스크모형 검증은 금융회사 원장 데이터의 구조·품질에 크게 의존합니다. 공개 데이터나 합성 데이터로는 실제 업무 적합성을 입증할 수 없습니다.
2. **미인가 스타트업의 구조적 제약** — 당사는 금융회사가 아니므로 독자적으로 리스크모형 검증 업무를 수행할 수 없습니다. 금융회사에 서비스를 위탁하여 시범 운영하는 방식이 유일한 실증 경로입니다.
3. **내부통제 관점의 제3자 검증 필요** — 4-Eyes 승인, 감사추적 등 통제 장치가 실제 금융회사의 내부통제 기준을 충족하는지는 금융회사 준법·감사 부서의 평가를 거쳐야 확인 가능합니다.
