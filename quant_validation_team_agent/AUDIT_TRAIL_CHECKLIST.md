# 감사추적 체크리스트

## 1. 목적

검증 요청부터 최종 조직 결정까지 입력자료, 계산엔진 결과, 정책문서, Agent 산출물, 인간 검토 기록을 재현 가능하게 보관한다.

## 2. 공통 가정 및 통제

- 감사추적이 불충분하면 판정 확정이 아니라 `Gray` 후보로 처리한다.
- 수치 결과는 계산엔진 결과 ID와 입력 데이터 ID를 함께 기록한다.
- 최종 판단은 인간 검증자 및 공식 조직의 결정 기록으로 완결된다.

## 4. 재현성 요구사항

- 입력자료와 계산엔진 결과는 버전 또는 해시를 기록한다.
- 계산엔진 결과는 동일 입력, 동일 버전, 동일 설정으로 재실행 가능한 수준이어야 한다.
- 보고서 초안과 Action Notice는 원본 입력과 연결되는 식별자를 포함해야 한다.
- 수동 수정이 발생하면 수정자, 수정일시, 수정 사유를 기록한다.
- 동일 `case_fingerprint`의 반복 실행 결과가 동일한지 비교하고 불일치 시 재현성 결함으로 기록한다.

## 5. 감사추적 누락 시 처리

| 누락 항목 | 기본 처리 | 후속조치 |
|---|---|---|
| 계산엔진 결과 ID | Gray | 결과 ID 및 실행 로그 제출 요청 |
| 정책문서 버전 | Gray | 승인 정책문서 버전 확인 요청 |
| `regulatory_source_reference` | Gray | `BASEL_FSS_CONTROL_MAPPING.md`의 표준 출처 ID와 기준일/국내 적용 여부 제출 요청 |
| lineage 증적 | Gray | 원천계-계산엔진 매핑 제출 요청 |
| 인간 검토 기록 | Gray | 인간 검증자 검토 완료 전 판정 확정 불가, Action Notice 생성 필요 |
| Action Notice ID | 프로세스 결함 | Notice 생성 후 감사추적 보완 |
