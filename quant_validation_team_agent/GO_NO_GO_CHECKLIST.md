# 운영 전 Go/No-Go 체크리스트

## 1. 목적

양적검증 팀 에이전트를 운영에 투입하기 전 정책 정합성, 계산엔진 연계, 데이터 접근권한, 감사추적, 보고서, Action Notice, UAT, 교육, 규제 변경 통제, 비상중지 절차를 최종 점검한다.

## 2. 공통 가정 및 No-Go 원칙

- LLM 계산 방지 통제가 미흡하면 No-Go다.
- `Amber` 용어 필터가 미흡하면 No-Go다.
- Gray 조건이 누락되면 No-Go다.
- Yellow/Red/Gray에서 Action Notice가 생성되지 않으면 No-Go다.
- 인간 최종 판단권을 오인시킬 가능성이 있으면 No-Go다.
- 감사추적이 불충분하면 No-Go다.
- 동일 요청에 동일 결과가 나오지 않거나 fingerprint 체계가 없으면 No-Go다.
- 신용·시장·운영·금리·유동성·전략·평판·자본적정성집계(`capital_adequacy_aggregation`)·복합리스크(`multi_risk_or_unclear`) 전 산출 영역 분류 기준이 없으면 No-Go다.
- 최신 Basel/FSS/국내 감독기준 출처 확인 절차가 없으면 No-Go다.

## 4. No-Go 조건

- LLM이 직접 수치 계산 또는 정량 추정을 수행할 수 있는 프롬프트/워크플로우가 남아 있다.
- 계산엔진 결과 없이 수치 결론 또는 Green 판정 후보를 낼 수 있다.
- `Amber`가 출력 판정 라벨로 사용될 수 있다.
- 정책 미정의, 데이터 부족, 표본 부족, 권한 부족, lineage 불명확, 증적 부족이 Gray로 전환되지 않는다.
- Yellow/Red/Gray에서 Action Notice가 누락된다.
- Green을 최종 승인, 검증 완료, 규제 적합 확정처럼 표현한다.
- 규제 변화가 공식 승인 없이 정책·모형·계산엔진·보고서에 자동 반영될 수 있다.
- 감사추적에 입력자료, 계산결과 ID, 정책문서 버전, 감독기준 출처, 인간 검토 기록이 빠진다.
- 동일 fingerprint 반복 실행에서 다른 판정 후보 또는 다른 Action Notice 필요 여부가 나온다.

## 5. 최종 결정 양식

```markdown
# Go/No-Go 결정
- 평가일:
- 평가자:
- 대상 버전:
- UAT 결과 요약:
- 미해결 결함:
- 잔여위험:
- 결정: Go | Conditional Go | No-Go
- 조건부 Go 조건:
- 공식 승인자:
- 승인일:
```

## 6. 운영 후 모니터링

- 초기 1개월은 모든 비Green Notice를 샘플링 없이 전수 검토한다.
- Green 보고서도 최종 승인 아님 문구와 수치 출처 표기 준수 여부를 점검한다.
- 규제 변화 후보 통제는 정책 담당부서 승인 전 운영 적용 여부를 점검한다.
