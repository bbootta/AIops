# 판정 정책 템플릿

## 1. 목적

양적검증 팀 에이전트가 일관된 판정 후보를 작성하도록 `Green`, `Yellow`, `Red`, `Gray` 정의와 후속조치를 표준화한다.

## 2. 공통 가정 및 금지사항

- 판정 후보는 최종 승인 또는 공식 조직 판단이 아니다.
- LLM은 직접 수치 계산을 하지 않으며, 계산엔진 결과 없이는 정량 결론을 내리지 않는다.
- `Amber` 용어는 금지한다.
- 정책 미정의, 데이터 부족, 표본 부족, 권한 부족, lineage 불명확, 증적 부족은 `Gray`다.

## 3. 판정 정의

| 판정 | 정의 | 필수 후속조치 |
|---|---|---|
| Green | 제공된 공식 증적과 계산엔진 결과 기준 중대한 이슈 후보가 발견되지 않은 상태. 최종 승인 아님. | 검토 근거, 제한사항, 인간 검토 필요사항 기록 |
| Yellow | 보완 필요, 제한적 이슈, 영향이 제한적일 가능성이 있는 통제 미흡 또는 설명 필요 상태 | Action Notice 생성, 보완자료 및 재검증 조건 지정 |
| Red | 중대한 결함, 정책 위반, 결과 신뢰성 훼손 가능성, 규제·내부통제상 중대 이슈 후보 | Action Notice 생성, 에스컬레이션 후보 표시, 공식 조직 검토 요청 |
| Gray | 정책 미정의, 데이터 부족, 표본 부족, 권한 부족, lineage 불명확, 증적 부족 등 판단 불가 상태 | Action Notice 생성, 판단불가 사유코드와 필요 증적 지정 |

## 4. 판정 작성 양식

```markdown
## 판정 후보
- provisional_judgement: Green | Yellow | Red | Gray
- 판정 근거:
- 사용한 정책문서 및 버전:
- 계산엔진 결과 참조:
- 주요 발견사항:
- 제한사항:
- Action Notice 필요 여부:
- 인간 검증자 확인사항:
```

## 5. 판정 우선순위

1. 금지 요청, 공식 기준 출처 불명확, 국내 적용 여부 불명확, 동일 fingerprint 결과 불일치가 있으면 `Gray`를 우선 검토한다.
2. `risk_output_domain`이 불명확하거나 복수 영역 영향의 주영역 근거가 없으면 독립 게이트로 `Gray`를 우선 검토한다.
3. Gray 조건이 있으면 정량 결과가 일부 존재하더라도 우선 `Gray`를 검토한다.
4. 명확한 정책 위반 또는 신뢰성 훼손 후보가 있으면 `Red`를 검토한다.
5. 보완 가능하고 영향이 제한적일 가능성이 있으면 `Yellow`를 검토한다.
6. 중대 이슈 후보가 없고 증적이 충분한 경우에만 `Green` 후보를 작성한다.
7. Green이라도 최종 승인 아님 문구를 반드시 포함한다.

## 6. Gray 사례 라이브러리

| 사례명 | 입력상황 | 사용 가능한 증적 | 부족한 증적 | 판정 후보 | Action Notice | 인간 검증자 확인사항 |
|---|---|---|---|---|---|---|
| 정책 미정의 | 신규 거시변수 검증 기준이 공식 정책에 없음 | 변수 설명, 사용 목적 | 승인된 검증 기준 또는 정책 예외 승인 | Gray | 필요 | 정책 담당부서 기준 수립 필요 여부 |
| 데이터 부족 | PD 검증 대상 기간 중 일부 월 데이터 누락 | 일부 기간 데이터 | 누락 기간 데이터 또는 제외 승인 | Gray | 필요 | 누락 영향과 재추출 가능성 |
| 표본 부족 | 특정 등급 또는 상품군 default 표본 부족 | 표본 요약 | pooling/기간 확장 정책 | Gray | 필요 | 대체 검증방법 허용 여부 |
| 권한 부족 | LGD 담보 회수자료 접근권한 없음 | 방법론 문서 | 회수자료 또는 대체 공식 증적 | Gray | 필요 | 권한 승인 경로 |
| Lineage 불명확 | 계산엔진 입력과 원천계 매핑 불명확 | 결과 파일 | ETL, 추출쿼리, 변환로직 | Gray | 필요 | 재현성 충족 전 판단 보류 여부 |
| 증적 부족 | 계산 숫자는 있으나 로그와 버전이 없음 | 결과 캡처 | 실행 로그, 엔진 버전, 파라미터 파일 | Gray | 필요 | 결과 신뢰성 인정 여부 |

## 7. 비Green Action Notice 연결

- `Yellow`: 보완 필요 사유와 완료기한을 명시한다.
- `Red`: 에스컬레이션 후보와 업무영향을 명시한다.
- `Gray`: 사유코드(`POLICY_UNDEFINED`, `DATA_INSUFFICIENT`, `SAMPLE_INSUFFICIENT`, `ACCESS_LIMITED`, `LINEAGE_UNCLEAR`, `EVIDENCE_INSUFFICIENT`)와 필요 증적을 명시한다.

## 8. 동일 요청-동일 결과 요구사항

- 판정 전 `case_fingerprint`와 `case_fingerprint_status`를 기록한다.
- 동일 fingerprint의 과거 판정 후보가 있으면 현재 판정 후보와 비교한다.
- 불일치 시 정책·데이터·계산엔진 버전 변경으로 설명되지 않는 한 `Gray`와 Action Notice를 생성한다.
- 판정 근거에는 적용된 결정 우선순위 단계와 tie-break 규칙을 명시한다.

### tie-break 규칙

| 우선순위 | 적용 조건 | 결정 |
|---|---|---|
| 1 | Gray 조건과 다른 판정 조건 동시 존재 | Gray 우선 |
| 2 | Red와 Yellow 조건 동시 존재 | 공식 정책 위반 또는 신뢰성 훼손 가능성이 명시 증적으로 뒷받침되면 Red, 아니면 Yellow |
| 3 | Green 조건이지만 증적 일부 부족 | Yellow 검토 |
| 4 | 동일 fingerprint 과거 판정과 현재 판정 불일치 | Gray (재현성 결함) |
| 5 | 동등한 우선순위 조건 충돌로 판단 불가 | Gray (판단 불가), 인간 검증자 확인 요청 |
