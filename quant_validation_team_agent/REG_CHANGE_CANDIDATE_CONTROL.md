# 규제 변화 후보 검증통제 제안 프로세스

## 1. 목적

규제 변화가 리스크 검증업무에 미칠 수 있는 영향을 식별하고 후보 검증통제를 제안하되, 공식 정책 반영과 운영 적용은 인간 담당자 및 승인 조직의 통제로 남긴다.

## 2. 공통 가정 및 금지사항

- 규제 변화는 자동 반영하지 않는다.
- LLM은 후보 영향분석과 후보 검증통제 제안까지만 수행한다.
- 공식 정책 반영, 모형 변경, 계산엔진 설정 변경, 보고서 기준 변경은 인간 담당자 및 승인 조직이 수행한다.
- 판정 라벨은 `Green`, `Yellow`, `Red`, `Gray`만 사용하고 `Amber`는 사용하지 않는다.
- 규제 원문 또는 공식 출처가 불명확하면 `Gray`로 처리한다.
- Basel/FSS/국내 감독기준은 기준일, 시행일, 국내 적용 여부, 내부 정책 반영 여부를 분리해 기록한다.

## 3. 프로세스

| 단계 | 활동 | 산출물 | 중지/Gray 조건 |
|---:|---|---|---|
| 1 | 규제 원문 출처 확인 | 출처 URL/문서 ID, 발행기관, 발행일 | 출처 불명확 |
| 2 | 변경 요약 작성 | 변경 전/후 요약, 시행일 후보 | 원문 접근 불가 |
| 3 | 영향 가능 업무 식별 | 관련 모델, 파라미터, 보고서, 데이터 | 업무 매핑 불명확 |
| 4 | 후보 통제 제안 | 검증 체크포인트, 필요 데이터, 정책 변경 후보 | 정책 담당부서 미확인 |
| 5 | 검토 필요 부서 지정 | 리스크감리, 모형개발, 리스크관리, 준법, IT 등 | 승인권자 불명확 |
| 6 | 승인 전 적용 금지 표시 | 자동 반영 금지 문구 | 사용자 자동 적용 요청 |

## 5. 운영상 주의사항

- 규제 변화 요약은 원문과 내부 정책 해석을 분리해 작성한다.
- 시행일이 명확하지 않으면 운영 반영 일정을 확정하지 않는다.
- 후보 통제는 UAT와 Go/No-Go 체크를 통과하기 전 운영 적용하지 않는다.
