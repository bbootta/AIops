# 문서 유형별 번역 관례 (Document Type Conventions)

회사 문서의 장르별 번역 전략. 문서 분석 단계에서 유형을 판정하고 해당 절의 규칙을 브리프에 반영한다.

## 유형 판정 기준

| 유형 | 신호 | 충실성↔자연스러움 축 |
|---|---|---|
| 이메일·메신저 | 인사말, 수신자 호칭 | 자연스러움 우선 |
| 사내 공지 | 전체 공지 형식, 시행일 | 자연스러움 우선 |
| 보고서·기획서 | 개조식, 표, 요약 | 균형 |
| 회의록 | 발언자, 결정사항, 액션아이템 | 균형 (결정사항은 충실성) |
| 기술 문서·매뉴얼 | 절차, 코드, UI 문자열 | 용어 정확성 우선 |
| 마케팅·홍보 | 슬로건, CTA, 브랜드 톤 | 자연스러움 극대화 (transcreation) |
| 계약·법무 | 조항 번호, 정의 조항, 당사자 | 충실성 극대화 |
| 공문서 (대관) | 문서번호, 수신·참조, 붙임 | 형식 규정 준수 |
| IR·재무 | 재무제표, 회계 용어 | 용어 정확성 + 충실성 |

## 유형별 규칙

### 이메일·사내 공지
- 인사말·맺음말은 도착어 관례로 **장르 변환**한다 (직역 금지). 예: "안녕하세요, ○○팀 김철수입니다" → "Hi team," / "Hello everyone,".
- 날짜·마감·장소 등 실무 정보는 오역 제로 원칙 — QA에서 별도 대조한다.

### 보고서·기획서
- 개조식(bullet) 구조 유지. 한국어 개조식 "~함/~임"은 영어에서 동사구 bullet("Completed X", "Plan to Y")로.
- Executive summary가 없는 한국어 보고서를 영어로 옮길 때도 구조를 임의 추가하지 않는다(요청 시에만).
- 숫자·지표는 원문과 1:1 대조 필수.

### 회의록
- 발언 뉘앙스보다 **결정사항·액션아이템의 정확성**이 우선.
- 발언자 직함·호칭은 용어집의 직급 매핑을 따른다.

### 기술 문서·매뉴얼
- UI 문자열은 실제 제품의 해당 언어 문자열을 확인해서 사용한다. 확인 불가 시 원문 병기: 「저장(Save)」.
- 코드 블록, 명령어, 파일 경로, API 이름은 번역하지 않는다.
- 절차 단계는 명령형 통일 (EN: imperative / KO: "~합니다" 또는 "~하세요" 통일).

### 마케팅·홍보 (Transcreation)
- 슬로건·헤드라인은 직역하지 않고 **효과 등가**로 재창작한다. 2~3개 대안 + 직역 백트랜슬레이션을 함께 제시해 선택할 수 있게 한다.
- 문화 참조·언어유희는 도착 문화의 등가물로 대체하거나 제거를 제안한다.

### 계약·법무
- **형태 충실성 최우선**. 문장을 나누거나 합치지 않는다. 조항 번호·정의어 대문자 관례(영문 계약의 "Agreement", "Party") 유지.
- 확립된 법률 용어 대응을 사용한다 (해지 → termination, 손해배상 → damages, 불가항력 → force majeure).
- 애매한 조항은 절대 자연스럽게 '해석'하지 말고 `[TN]`으로 원문 중의성을 보존·보고한다.
- 최종본에 "번역본이며 법적 효력은 원본에 있음" 고지 필요 여부를 사용자에게 확인한다.

### 공문서 (대관 제출·수신)
- 한국어 공문서 작성·검토는 행안부 규정 기반의 `korean-official-document` 스킬이 별도로 존재한다. **한국어 공문서가 도착물인 경우 해당 스킬을 함께 사용한다.**
- 영→한 공문 번역 시 문서번호·수신·참조·붙임·"끝." 표시 등 한국 공문서 형식을 적용한다.

### IR·재무
- 회계 기준 용어(K-IFRS/IFRS/GAAP)의 공식 영문·국문 대응을 따른다 (매출액 → revenue, 영업이익 → operating profit, 당기순이익 → net income).
- 만/억/조 ↔ million/billion 환산 오류는 치명적 — QA에서 전수 대조한다.
