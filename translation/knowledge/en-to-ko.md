# 영→한 번역 가이드 (English → Korean)

영어 원문을 자연스러운 한국어로 옮길 때의 핵심 변환 규칙. 목표는 "한국어로 처음 작성된 문서"이며, 최대 적은 번역투 제거다.

## 1. 번역투 제거 (최우선)

| 번역투 (✗) | 자연스러운 한국어 (✓) | 원인 패턴 |
|---|---|---|
| ~에 대하여/대한 | ~을/를, ~ 관련 | about, on, regarding |
| ~을 통해 | ~로, ~해서 | through, via |
| ~에 의해 …되다 | 능동문으로 전환 | by + 수동태 |
| ~을 가지다 | ~이 있다 | have |
| ~들 (남용) | 복수 표지 생략 | plural -s |
| 그/그녀/그것 (남용) | 명사 반복 또는 생략 | he/she/it |
| 가장 ~한 것 중 하나 | 손꼽히는, 대표적인 | one of the most |
| ~하는 것이 요구된다 | ~해야 한다 | be required to |
| ~함에 있어 | ~할 때 | in doing |
| ~로부터 | ~에서 | from |
| 만약 ~한다면 | ~하면 ("만약" 생략) | if |
| ~뿐만 아니라 …도 (기계적) | 문장 재구성 | not only... but also |
| 다른 무엇보다도 | 특히, 무엇보다 | above all |

- **수동태 → 능동태**: 영어 수동태의 70% 이상은 한국어에서 능동으로 바꾸는 것이 자연스럽다. "The report was approved by the board" → "이사회가 보고서를 승인했다". 행위자를 숨기는 것이 목적인 수동태만 "~되다"로 유지한다.
- **대명사 → 생략/명사 반복**: 한국어는 문맥이 명확하면 주어·목적어를 생략한다. "it", "this", "they"를 기계적으로 옮기지 않는다.
- **무생물 주어 구문 해체**: "This document explains..." → "이 문서는 ~를 설명한다"(허용) 대신 문맥에 따라 "이 문서에서는 ~를 설명한다"가 더 자연스러운 경우가 많다. "The data shows that..." → "데이터를 보면 ~".

## 2. 격식(존댓말) 결정

문서 유형별 기본 어체 (`document-types.md`와 연동):

| 문서 유형 | 어체 |
|---|---|
| 사내 공지, 이메일 | 합쇼체/해요체 혼용 ("~합니다", "~해 주세요") |
| 보고서, 기획서 | 개조식 또는 "~함/~임" 종결, 서술형이면 "~한다" |
| 매뉴얼, 기술문서 | "~합니다" 또는 "~한다" (문서 내 통일) |
| 마케팅, 대외 홍보 | "~합니다" + 브랜드 톤 |
| 계약서, 법무 | "~한다", 법률문장 관례 |

- **문서 전체에서 어체를 통일한다.** 개조식과 서술식을 한 문단 안에서 섞지 않는다.
- 영어의 명령문(Do this...)은 매뉴얼에서 "~하세요/~합니다", 개조식에서는 "~할 것" 또는 명사형.

## 3. 외래어 표기

- 국립국어원 외래어 표기법을 따른다. 자주 틀리는 예: contents → 콘텐츠(컨텐츠 ✗), application → 애플리케이션(어플리케이션 ✗), workshop → 워크숍(워크샵 ✗), leadership → 리더십(리더쉽 ✗).
- **IT·비즈니스 관용 외래어는 무리하게 순화하지 않는다**: 이슈, 리스크, 프로세스, 마일스톤 등 사내에서 통용되는 표현은 유지. 판단 기준은 용어집과 대상 독자.
- 널리 통용되는 영문 약어(KPI, ROI, API, OKR)는 영문 그대로 두는 것을 기본으로 한다. 첫 등장 시 필요하면 "핵심성과지표(KPI)"처럼 병기.

## 4. 정보 구조 조정

- 영어의 "결론 → 상세" 구조는 한국어 비즈니스 문서에서도 통용되므로 유지하되, 문장 내부에서는 한국어 어순(수식어 → 피수식어, 종속절 → 주절)으로 재배열한다.
- 긴 영어 문장(관계절 2개 이상)은 한국어에서 2문장으로 나누는 것을 우선 검토한다.
- 콜론·세미콜론·대시는 한국어 문장부호 관례로 변환한다 (콜론 나열 → "다음과 같다", 대시 삽입구 → 쉼표나 괄호).

## 5. 어휘 선택

- 사전 1번 뜻을 경계한다: available → "이용 가능한"(✗) → 문맥별 "쓸 수 있는/판매 중인/시간이 되는", address → "다루다/해결하다/대응하다", support → "지원하다/뒷받침하다/고객 지원".
- 영어 강조 표현의 과잉 번역 주의: "very", "really", "great"를 전부 "매우/정말/훌륭한"으로 옮기면 과장된 문서가 된다. 한국어 격식 문서 관례에 맞게 절제한다.
- 단위·숫자: `style-formatting.md` 적용. million/billion → 백만/십억 직역 대신 만/억 단위로 환산 (예: $3 million → 300만 달러, 12 billion won → 120억 원).
